## 1. 总览：库职责边界与全局原则

> 全局设计原则与开发规范统一见 [`docs/开发规范.md`](./开发规范.md)（§2 红线、§3.3 服务凭证、§5 凭证矩阵）；本文 §1.2 为原则摘要，细节以开发规范为准。

### 1.1 双库职责边界

| 库 | 归属服务 | 职责 | 权威边界 |
|----|----------|------|----------|
| `iam_identity` | iam-authorization-server（认证中心） | 身份与凭据、OAuth2 协议数据、租户目录、令牌签发准入 | **身份权威**（IdP 自持用户源，凭据零外传） |
| `iam_authorization` | iam-resource-service（资源中心） | 业务 RBAC、应用目录与授权、组织、接口准入、开放能力 | **业务授权权威** |
| Redis | 认证中心 / 资源中心 | 登录会话（Spring Session）、Access/Refresh Token 运行时、撤销即删 | 非 DB 范围（持久化取舍见 §6，R3 暂缓） |

### 1.2 全局设计原则

| # | 原则 | 说明 | 落点 |
|---|------|------|------|
| P1 | **编码寻址** | 跨库 / 对外引用一律用业务编码（`user_code`、`tenant_code`、`sys_role.code`、`iam_org.org_code`、`client_id`），内部自增主键**不下放** | 所有 `sys_*` 关系表与 `iam_*` 业务表 |
| P2 | **跨库逻辑引用** | 跨库**不建外键、不做 join**；语义靠编码引用，由服务间接口解析（目录 API / 内省 / 内部角色供给） | §2 跨库关联清单 |
| P3 | **单一权威** | 凭据/账号状态=认证中心；业务角色权限=资源中心；租户目录=认证中心；OAuth2 客户端=认证中心 | §3 / §4 归属 |
| P4 | **密钥零落库（方案 A）** | 客户端明文密钥不落任何业务库；密文（BCrypt）只在认证中心，明文仅创建/重置一次性返回 | `oauth2_registered_client` ↔ `iam_application_channel` |
| P5 | **表驱动准入** | 令牌签发准入（`iam_client_policy`）、资源接口准入（`iam_endpoint_policy`）、开放能力（登记+订阅）均由表驱动，yaml/代码硬编码退出 | 认证中心 + 资源中心 |
| P6 | **令牌 sub = user_code** | OAuth2 令牌主体标识即业务用户编码，贯穿 RBAC 关联、应用授权、门户查询 | 内省/claims/门户 |
| P7 | **去影子用户** | 资源中心**不镜像用户表**，RBAC 与授权按 `user_code` 直接关联（V6.2 已删影子表） | `sys_user_role` |

## 2. 库边界与跨库数据关联

### 2.1 边界图

```
┌─────────────────────────────────────┐        ┌─────────────────────────────────────┐
│ 认证中心  iam_identity（8 表）        │        │ 资源中心  iam_authorization（11 表）   │
│  身份/凭据  sys_user                 │        │  业务 RBAC  sys_role/…/sys_user_role  │
│  外部身份   iam_external_identity    │◄──────►│  应用目录   iam_application/_channel   │
│  租户       iam_tenant(_user)        │ 编码关联 │  组织        iam_org                   │
│  OAuth2     oauth2_* 三表            │  逻辑引用 │  应用授权   iam_app_authorization     │
│  签发准入   iam_client_policy        │        │  接口准入   iam_endpoint_policy         │
│                                      │        │  开放能力   iam_api_capability/_sub     │
└───────────────┬─────────────────────┘        └───────────────┬─────────────────────┘
        │ 身份权威：本地认证 / 令牌 / 内省 / 客户端目录 API                 ▲ 业务授权权威：内省 + RBAC + 授权
        └────────────────── Redis（会话 / Token 运行时）────────────────────┘
```

- **不建跨库外键、不做跨库 JOIN**：跨库语义全部通过**业务编码**关联，具体值由服务间接口解析（认证中心目录/内省接口、资源中心内部角色供给接口）。
- 同库内的关联使用主键或业务编码，见各表「关键逻辑」。

### 2.2 跨库关联清单（核心）

| 源库.表.字段 | 目标库.表.字段 | 方向 | 说明 |
|--------------|----------------|------|------|
| identity.`sys_user.user_code` | authz.`sys_user_role.user_code` | identity → authz | 用户-角色绑定，`token sub = user_code`，认证中心经 `/api/internal/user/{userCode}/roles` 读取 |
| identity.`iam_tenant.tenant_code` | authz.`iam_application / iam_org / iam_app_authorization / iam_api_capability / iam_capability_subscription .tenant_code` | identity → authz | 业务数据归属租户，编码引用（非 FK） |
| identity.`oauth2_registered_client.client_id` | authz.`iam_application_channel.sso_client_id` | identity → authz | 渠道绑定独立 SSO 客户端（密钥零落库，方案 A） |
| identity.`oauth2_registered_client.client_id` | authz.`iam_capability_subscription.client_id` | identity → authz | 开发者客户端订阅开放能力 |
| identity.`oauth2_registered_client.client_id` | identity.`iam_client_policy.client_id` | 同库 | 客户端签发准入策略 |
| identity.`oauth2_registered_client.id(client_id)` | identity.`oauth2_authorization_consent / oauth2_authorization_record .registered_client_id` | 同库 | 授权同意 / 授权历史（注：consent/record 存的是 client 主键 id，见 3.2 备注） |
| identity.`sys_user.user_code` | identity.`iam_tenant_user.user_code / iam_external_identity.user_code` | 同库 | 租户成员 / 第三方绑定 |
| authz.`sys_role.code` | authz.`iam_app_authorization.subject_id`（subject_type=ROLE） | 同库 | 应用授权主体=角色编码 |
| authz.`iam_org.org_code` | authz.`iam_app_authorization.subject_id`（subject_type=ORG） | 同库 | 应用授权主体=组织编码 |
| authz.`iam_api_capability.capability_code` | authz.`iam_capability_subscription.capability_code` | 同库 | 能力订阅 |

> **注意**：`oauth2_authorization_consent.registered_client_id` / `oauth2_authorization_record.registered_client_id` 在基线与 Spring Authorization Server 实现中存的是 `oauth2_registered_client.id`（UUID 主键）；对外展示与业务引用一律用 `client_id`。`iam_client_policy`、渠道 `sso_client_id`、能力订阅等则直接引用 `client_id`（业务编码）。

## 3. 认证中心（`iam_identity` · 8 表）

### 3.1 身份与租户

#### 3.1.1 `sys_user` —— 用户凭据主库（全量 IdP）

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 主键ID（仅内部联表使用，**不下放**） |
| user_code | varchar(64) UQ | ✅ | **业务用户编码**（对外/下放引用，`token sub`；资源中心与业务应用只认此编码） |
| username | varchar(100) UQ | ✅ | 登录用户名 |
| password | varchar(200) | ✅ | BCrypt 加密密码 |
| nickname | varchar(100) | ❌ | 昵称 |
| email | varchar(200) | ❌ | 邮箱 |
| phone | varchar(50) | ❌ | 手机号 |
| avatar | varchar(500) | ❌ | 头像 URL |
| user_label | varchar(30) | ✅ | 业务标签（**仅展示/审计，不参与准入判定**）：admin=管理端 / client=客户端 / wechat=微信端 |
| enabled | tinyint(1) | ✅ | 1=启用 0=禁用 |
| account_non_expired | tinyint(1) | ✅ | 1=未过期 0=已过期 |
| account_non_locked | tinyint(1) | ✅ | 1=未锁定 0=已锁定（**现状无锁定逻辑**，见一级清单 A1） |
| credentials_non_expired | tinyint(1) | ✅ | 1=未过期 0=已过期 |
| create_time / update_time | datetime | ✅ | 创建 / 更新时间 |

**关键逻辑**：
- 登录=本地库查询 + BCrypt 校验，**零远程凭据调用**；`loadUserByUsername` 按 username、设备码链路按 `user_code` 反查（`loadUserByUserCode`）。
- 令牌 `principal name = user_code`；业务 RBAC 由 `RemoteRoleService` 按 `user_code` 从资源中心供给（D6，已接线），含 `ADMIN` 角色时注入 `ADMIN_SERVICE_TOKEN`；资源中心不可达时降级 `user_label` 映射（`ADMIN_SERVICE_TOKEN` / `ROLE_USER`）并告警。
- 删除/重置/禁用联动：认证中心调用资源中心 `DELETE /api/admin/users/{userCode}/data`（管理 M2M 服务凭证，admin-m2m）清理按 user_code 的授权残留，并强制下线会话。
- `user_code` 生成规则：`u_` + 32 位十六进制（演示种子见 §7）。

#### 3.1.2 `iam_external_identity` —— 外部身份绑定表（V6.7，仅建表）

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 主键ID |
| user_code | varchar(64) | ✅ | 本地业务用户编码（关联 `sys_user.user_code`） |
| provider | varchar(30) | ✅ | 第三方提供商：`wechat`/`wecom`/`dingtalk`/`alipay`/`google`/`github` |
| provider_open_id | varchar(200) | ✅ | 第三方唯一标识（openid/sub/登录标识） |
| union_id | varchar(200) | ❌ | 第三方开放平台统一标识（unionid，微信系多端通用） |
| nickname | varchar(100) | ❌ | 第三方昵称（仅展示，不覆盖本地） |
| avatar | varchar(500) | ❌ | 第三方头像 URL（仅展示） |
| status | tinyint(1) | ✅ | 1=已绑定有效 0=已解绑 |
| create_time / update_time | datetime | ✅ | 首次绑定 / 更新时间 |

**关键逻辑**：唯一键 `uk_provider_open_id(provider, provider_open_id)` —— 同一第三方身份至多绑定一个本地用户；绑定/解绑逻辑与第三方 OAuth2/OIDC 登录链路待二级清单 B1 接入。

#### 3.1.3 `iam_tenant` —— 租户目录（身份层权威）

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 租户ID |
| tenant_code | varchar(64) UQ | ✅ | 租户编码（对外引用用编码） |
| tenant_name | varchar(100) | ✅ | 租户/企业名称 |
| status | tinyint(1) | ✅ | 1=启用 0=禁用 |
| create_time / update_time | datetime | ✅ | 创建 / 更新时间 |

**关键逻辑**：租户目录权威在认证中心；资源中心业务表仅存 `tenant_code` 编码引用，不做 FK、不做 join。

#### 3.1.4 `iam_tenant_user` —— 租户成员关系

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 关联ID |
| tenant_code | varchar(64) | ✅ | 租户编码（关联 `iam_tenant.tenant_code`） |
| user_code | varchar(64) | ✅ | 业务用户编码（关联 `sys_user.user_code`） |
| tenant_username | varchar(100) | ❌ | 租户内账号（可空，默认同全局用户名） |
| status | tinyint(1) | ✅ | 1=正常 0=停用 |
| create_time / update_time | datetime | ✅ | 创建 / 更新时间 |

**关键逻辑**：一人可属多租户；V6.4 由 `tenant_id/user_id` 数值改为 `tenant_code/user_code` 编码（编码化引用，`uk_tenant_user`）。

### 3.2 OAuth2 协议数据

#### 3.2.1 `oauth2_registered_client` —— OAuth2 客户端注册表

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | varchar(100) PK | ✅ | 客户端主键（UUID） |
| client_id | varchar(100) | ✅ | 客户端标识符（**对外公开、业务引用**） |
| client_id_issued_at | datetime | ❌ | 客户端 ID 签发时间 |
| client_secret | varchar(200) | ❌ | 客户端密钥（**BCrypt 密文**；PKCE 客户端可空） |
| client_secret_expires_at | datetime | ❌ | 密钥过期时间（NULL=永不过期） |
| client_name | varchar(200) | ❌ | 客户端名称（展示用） |
| client_authentication_methods | varchar(1000) | ✅ | 认证方式：client_secret_basic / client_secret_post / none / private_key_jwt |
| authorization_grant_types | varchar(1000) | ✅ | 授权类型：authorization_code / client_credentials / refresh_token / password / device_code |
| redirect_uris | varchar(1000) | ❌ | 回调地址（逗号分隔） |
| post_logout_redirect_uris | varchar(1000) | ❌ | 登出后重定向（逗号分隔） |
| scopes | varchar(1000) | ✅ | 授权范围（openid,profile,email,read,write） |
| client_settings | varchar(2000) | ✅ | 客户端设置 JSON：`requireProofKey` / `requireAuthorizationConsent` |
| token_settings | varchar(2000) | ✅ | 令牌设置 JSON：accessTokenFormat(REFERENCE/SELF_CONTAINED)、TTL、reuseRefreshTokens、idTokenSignatureAlgorithm |

**关键逻辑**：
- **密钥零落库（方案 A）**：明文 `client_secret` 仅创建/重置时一次性返回；密文 BCrypt 仅在此表；资源中心渠道表只存 `sso_client_id` 标识 + `secret_status` 状态位。
- 令牌为 **Opaque**（accessTokenFormat=reference），撤销即删 Redis key；`requireAuthorizationConsent` 控制是否弹授权确认。
- 演示客户端：`resource-server`/`admin-app`/`portal-app`/`web-app`/`device-app`/`mobile-app`/`service-app`（见 §7）。

#### 3.2.2 `oauth2_authorization_consent` —— 授权确认表

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| registered_client_id | varchar(100) | ✅ | 客户端主键 id（复合主键 1） |
| principal_name | varchar(200) | ✅ | 主体（user_code）（复合主键 2） |
| authorities | varchar(2000) | ✅ | 授予的权限（逗号分隔 scope） |
| first_grant_time | datetime | ❌ | 首次授权时间（insert 时写，更新不改动） |

**关键逻辑**：与 Spring Authorization Server 协议对齐（`registered_client_id` 为主键 id）；授权确认随 `requireAuthorizationConsent=true` 的客户端触发。

#### 3.2.3 `oauth2_authorization_record` —— 授权记录（历史日志）

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 主键ID |
| registered_client_id | varchar(100) | ✅ | 客户端主键 id |
| client_name | varchar(200) | ❌ | 客户端名称（冗余，方便查询展示） |
| principal_name | varchar(200) | ✅ | 授权主体（user_code） |
| granted_authorities | varchar(2000) | ✅ | 授予权限（scope，逗号分隔） |
| grant_time | datetime | ✅ | 授权时间 |
| revoke_time | datetime | ❌ | 撤销时间（status=revoked 有值） |
| status | varchar(20) | ✅ | active=有效 / revoked=已撤销 |
| grant_type | varchar(100) | ❌ | authorization_code / device_code / password 等 |

**关键逻辑**：**只记历史，不是 OAuth2 运行时状态**。授权码/Access/Refresh 运行时与在线会话仅存 Redis（重启即丢，取舍见 §6 / R3）。管理端「在线会话 / 授权记录」页面读取本表 + Redis。

### 3.3 签发准入配置

#### 3.3.1 `iam_client_policy` —— 客户端准入策略（原 yaml 表化，V6.1）

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 主键ID |
| client_id | varchar(100) UQ | ✅ | 客户端 ID（关联 `oauth2_registered_client.client_id`） |
| allowed_roles | varchar(1000) | ❌ | 允许访问该客户端的角色编码列表（逗号分隔；空或 `*` 表示不限制） |
| status | tinyint(1) | ✅ | 1=启用 0=停用（默认放行） |
| remark | varchar(500) | ❌ | 备注 |
| create_time / update_time | datetime | ✅ | 创建 / 更新时间 |

**关键逻辑**：令牌签发准入（fail-closed），管理端经 `/api/admin/policies` 维护；与资源中心接口准入（`iam_endpoint_policy`）分层。演示种子：`admin-app` 仅允许 `ADMIN`（管理后台）、`portal-app` 仅允许 `USER`（门户前端）。

## 4. 资源中心（`iam_authorization` · 11 表）

### 4.1 业务 RBAC（`sys_*` 四表，无影子用户表）

#### 4.1.1 `sys_permission` —— 权限表

| 列 | 类型 | 必填 | 说明 |
|----|------|:---:|------|
| id | bigint PK AI | ✅ | 权限ID |
| code | varchar(100) UQ | ✅ | 权限标识（如 `app:crm`） |

| 列 | 类型 | 必填 | 说明 |

| subject_type | varchar(20) | ✅ | 主体类型：ROLE=角色 / USER=用户 / ORG=组织 |

| 列 | 类型 | 必填 | 说明 |

| method | varchar(10) | ✅ | HTTP 方法：GET/POST/PUT/DELETE（ANY=全部） |
| path | varchar(255) | ✅ | 路径模式（Spring 注册模式） |
| required_authority | varchar(100) | ✅ | **准入要求**：`PERMIT_ALL`=放行 / `AUTHENTICATED`=任意凭证 / `ADMIN_SERVICE_TOKEN`=管理服务凭证 / `PORTAL_SERVICE_TOKEN`=门户服务凭证 / `CAPABILITY`=按开放能力订阅校验 |

## 5. 数据血缘与端到端串联

一条完整链路的表引用关系（**业务编码贯穿全链路**）：

```
sys_user(user_code) ──登录──► token(sub=user_code)
      │   ▲                         │
      │   └── claims: RemoteRoleService ──► sys_user_role ── sys_role ── sys_role_permission ── sys_permission
      │                                 (D6 内部接口, RBAC 权威在资源中心)
      ▼
oauth2_registered_client(client_id) ◄── iam_client_policy（签发准入）
      │
      ├──► iam_application_channel.sso_client_id（渠道 SSO, 密钥零落库）
      └──► iam_capability_subscription.client_id（能力订阅）
                                              │
门户: iam_application ── iam_app_authorization（ROLE/USER/ORG 编码主体）──► 门户可见应用
开放能力: /api/capability/** ── iam_endpoint_policy(CAPABILITY) + iam_api_capability + 订阅
```

| 编码 | 权威表 | 被引用处（跨库） |
|------|--------|------------------|
| `user_code` | `sys_user` | `sys_user_role`、`iam_tenant_user`、`iam_external_identity`、`iam_app_authorization.subject_id(USER)`、令牌 sub |
| `tenant_code` | `iam_tenant` | 资源中心 5 张 `tenant_code` 列 |
| `client_id` | `oauth2_registered_client` | `iam_client_policy`、`iam_application_channel.sso_client_id`、`iam_capability_subscription` |
| `sys_role.code` | `sys_role` | `iam_app_authorization.subject_id(ROLE)` |
| `org_code` | `iam_org` | `iam_app_authorization.subject_id(ORG)` |
| `capability_code` | `iam_api_capability` | `iam_capability_subscription` |

## 6. 一致性保障与已知取舍

### 6.1 一致性策略（跨服务无分布式事务）

- **编码寻址**：跨库以业务编码关联，天然可重入、可幂等。
- **幂等补偿**：渠道↔客户端等跨服务 CRUD 以认证中心为基线，资源中心失败回滚时清理孤儿（创建失败删孤儿客户端）。
- **失败兜底**：登录取角色失败→降级 user_label 映射（不锁死管理端）；门户跨库取目录失败→返回空列表并告警。
- **生命周期联动**：用户删除 → 资源中心 `DELETE /api/admin/users/{userCode}/data`（管理 M2M 服务凭证，admin-m2m，V6.9）清理授权残留 + 强制下线（D9 已闭环）。

### 6.2 已知取舍与演进

| 项 | 现状 | 去向 |
|----|------|------|
| OAuth2 授权/SSO 会话持久化（R3） | 仅 Redis，重启即丢 | 需恢复力/审计时引入 JDBC 授权服务 + Spring Session JDBC（DB 真源、Redis 缓存，不双写），一级清单 A4 |
| 登录失败锁定/限流（R4） | `account_non_locked` 等字段已具备、逻辑未实现 | 一级清单 A1 |
| 接口限流与调用计数 | QPS/配额仅登记断言，无计数表 | 二级清单 B5：`iam_capability_usage` 另表 |
| 管理面审计日志 | 无操作留痕 | 一级清单 A3（`iam_admin` 操作日志） |
| 组织人员归属 | `iam_org` 仅承载授权主体 | 二级清单 B3：组织树维护/人员归属 |
| 第三方登录 | `iam_external_identity` 仅建表 | 二级清单 B1：绑定/解绑 + 第三方 IdP 登录接入 |
| 迁移机制 | 基线 SQL + V6.x migration + 部分 Java Runner | 一级清单 A6：迁移/初始化收口 SQL |
