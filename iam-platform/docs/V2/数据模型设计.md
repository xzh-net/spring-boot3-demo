# 多租户多商户管理平台数据模型设计

> 文档版本：V2.0  
> 编制日期：2026-08-18  
> 关联文档：[多租户多商户管理平台推荐总体架构](./多租户多商户管理平台推荐总体架构.md)  
> 数据库范围：`iam_auth_db`、`iam_tenant_db`、`iam_resource_db`、`iam_portal_db`、`iam_open_db`

---

## 一、设计范围

本文按 V2 目标领域库设计数据模型，覆盖当前项目已有表及总体架构中规划新增的表。

当前 19 张表来源于物理库 `iam_identity`（8 张）和 `iam_authorization`（11 张）；本文描述迁移后的五库目标结构，不继续沿用这两个物理库作为领域边界。

| 目标数据库 | 职责 | 表数量 | 说明 |
|---|---|---:|---|
| `iam_auth_db` | 用户凭据、OAuth2/OIDC、会话、安全与审计 | 12 | 其中 3 张运行时持久化表为 P2 可选 |
| `iam_tenant_db` | 租户、商户、组织、成员、配置和套餐 | 10 | 接收当前分散在身份库、授权库的租户主数据 |
| `iam_resource_db` | 角色、权限、资源、应用授权和数据权限 | 10 | 现有 RBAC 必须增加租户作用域 |
| `iam_portal_db` | 应用、渠道、菜单、页面、组件和工作台 | 8 | 应用目录从当前授权库迁出 |
| `iam_open_db` | 开发者、第三方应用、API、订阅和调用统计 | 8 | 开放能力从当前授权库迁出 |
| 合计 |  | 48 | 19 张现有表，29 张新增或可选表 |

表状态定义：

- **保留**：当前已有，V2 沿用并按本文补充字段或约束。
- **迁移**：当前已有，但需要迁入新的目标领域库。
- **改造**：当前已有，字段或关联方式必须调整后才能满足 V2。
- **新增**：当前没有，需要新建。
- **可选**：当前由 Redis 承担，只有需要 JDBC 持久化和重启恢复时才建设。

## 二、全局设计规范

### 2.1 数据库规范

| 项目 | 约定 |
|---|---|
| 数据库 | MySQL 8.0 |
| 存储引擎 | InnoDB |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_0900_ai_ci` |
| 主键 | 内部表使用 `bigint unsigned` 自增；OAuth2/Spring 标准表保留框架规定主键 |
| 时间 | 使用 `datetime(3)`，应用和数据库统一按 UTC 存储 |
| 布尔值 | 使用 `tinyint(1)`，`1` 表示是/启用，`0` 表示否/停用 |
| 状态值 | 使用 `tinyint` 或 `varchar(20)`；禁止直接依赖数据库 `enum` |
| JSON | 结构可演进的配置使用原生 `json`；禁止在 JSON 中保存可独立查询的主关系 |
| 金额 | 使用 `decimal(18,2)`；本文涉及的容量和次数使用 `bigint` |
| 软删除 | 核心关系不使用通用 `deleted`；通过业务 `status` 和失效时间保留历史 |

### 2.2 编码与租户隔离

1. `user_code`、`tenant_code`、`merchant_code`、`org_code`、`app_code`、`client_id`、`resource_code` 是跨库引用编码。
2. 内部自增 `id` 只能在本库使用，禁止作为跨库 API 参数或消息字段。
3. 租户级唯一键必须包含 `tenant_code`，不能只对对象编码建立全局唯一键。
4. 平台公共角色、权限和资源使用保留租户标识 `__PLATFORM__`；该值禁止分配给普通租户。
5. 所有带 `tenant_code` 的查询必须由可信租户上下文注入，不接受调用方随意覆盖。
6. 跨库不建外键、不做跨库 JOIN，通过服务 API、事件或缓存校验编码有效性。

### 2.3 公共审计字段

除 OAuth2/Spring 框架标准表和纯关联表外，领域表默认包含：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| create_by | varchar(64) | 否 | NULL | 创建人 `user_code` 或服务编码 |
| create_time | datetime(3) | 是 | CURRENT_TIMESTAMP(3) | 创建时间 |
| update_by | varchar(64) | 否 | NULL | 最后修改人 `user_code` 或服务编码 |
| update_time | datetime(3) | 是 | CURRENT_TIMESTAMP(3) | 最后修改时间，更新时自动刷新 |

后续表字段中用“公共审计字段”表示以上四列；已有表只有 `create_time/update_time` 时，`create_by/update_by` 可随 V2 迁移补齐。

### 2.4 跨库逻辑关联

| 源字段 | 目标字段 | 说明 |
|---|---|---|
| 各库 `tenant_code` | `iam_tenant_db.iam_tenant.tenant_code` | 租户归属 |
| 各库 `user_code` | `iam_auth_db.sys_user.user_code` | 用户身份 |
| 各库 `client_id` | `iam_auth_db.oauth2_registered_client.client_id` | OAuth2 客户端 |
| `iam_resource_db.iam_app_authorization.app_code` | `iam_portal_db.iam_application.app_code` | 应用授权 |
| `iam_resource_db.iam_app_authorization.channel_code` | `iam_portal_db.iam_application_channel.channel_code` | 渠道授权 |
| `iam_tenant_db.iam_package_feature.target_code` | `iam_resource_db.iam_resource.resource_code` | 套餐功能 |
| `iam_open_db.iam_open_app_client.client_id` | `iam_auth_db.oauth2_registered_client.client_id` | 第三方应用客户端 |

## 三、`iam_auth_db` 数据模型

### 3.1 表清单

| 表名 | 状态 | 用途 |
|---|---|---|
| `sys_user` | 保留、增强 | 用户凭据和账号状态 |
| `iam_external_identity` | 保留、待接线 | 第三方身份绑定 |
| `oauth2_registered_client` | 保留 | OAuth2/OIDC 客户端 |
| `oauth2_authorization_consent` | 保留 | 用户授权同意 |
| `oauth2_authorization_record` | 保留 | 授权历史 |
| `iam_client_policy` | 保留 | 客户端登录准入 |
| `iam_login_attempt` | 新增 P0 | 登录失败、防爆破和锁定证据 |
| `iam_password_history` | 新增 P1 | 密码历史和禁止复用 |
| `iam_operation_audit` | 新增 P0 | 跨中心敏感操作审计 |

### 3.2 `sys_user`：用户凭据表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| id | bigint unsigned | 是 | 自增 | 内部主键 |
| user_code | varchar(64) | 是 | - | 用户业务编码，Token `sub` 使用该值 |
| username | varchar(100) | 是 | - | 登录用户名 |
| password | varchar(200) | 是 | - | BCrypt 密码摘要，不保存明文 |
| nickname | varchar(100) | 否 | NULL | 用户昵称 |
| email | varchar(200) | 否 | NULL | 邮箱 |
| phone | varchar(50) | 否 | NULL | 手机号 |
| avatar | varchar(500) | 否 | NULL | 头像 URL |
| user_label | varchar(30) | 是 | `client` | 展示标签，不作为授权依据 |
| enabled | tinyint(1) | 是 | 1 | 是否启用 |
| account_non_expired | tinyint(1) | 是 | 1 | 账号是否未过期 |
| account_non_locked | tinyint(1) | 是 | 1 | 账号是否未锁定 |
| credentials_non_expired | tinyint(1) | 是 | 1 | 密码凭据是否未过期 |
| locked_until | datetime(3) | 否 | NULL | 自动锁定截止时间，NULL 表示未临时锁定 |
| password_changed_time | datetime(3) | 否 | NULL | 最近一次修改密码时间 |
| create_time | datetime(3) | 是 | 当前时间 | 创建时间 |
| update_time | datetime(3) | 是 | 当前时间 | 更新时间 |

约束与索引：

- 主键：`pk_sys_user(id)`。
- 唯一键：`uk_sys_user_code(user_code)`、`uk_sys_user_username(username)`。
- 可选唯一键：邮箱或手机号作为登录标识时，对标准化后的非空值建立唯一约束。
- 索引：`idx_sys_user_status(enabled, account_non_locked)`。

### 3.3 `iam_external_identity`：外部身份绑定表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| id | bigint unsigned | 是 | 自增 | 主键 |
| user_code | varchar(64) | 是 | - | 本地用户编码 |
| provider | varchar(30) | 是 | - | `wechat/wecom/dingtalk/alipay/google/github` |
| provider_tenant_id | varchar(128) | 是 | 空字符串 | 第三方企业、应用或 Issuer 标识 |
| provider_open_id | varchar(200) | 是 | - | 第三方主体唯一标识 |
| union_id | varchar(200) | 否 | NULL | 第三方跨应用统一标识 |
| nickname | varchar(100) | 否 | NULL | 第三方昵称，仅展示 |
| avatar | varchar(500) | 否 | NULL | 第三方头像，仅展示 |
| status | tinyint(1) | 是 | 1 | 1=有效，0=解绑 |
| create_time | datetime(3) | 是 | 当前时间 | 首次绑定时间 |
| update_time | datetime(3) | 是 | 当前时间 | 更新时间 |

约束与索引：

- 唯一键：`uk_external_subject(provider, provider_tenant_id, provider_open_id)`。
- 索引：`idx_external_user(user_code, status)`、`idx_external_union(provider, union_id)`。
- 绑定前必须确认同一第三方主体未绑定其他本地用户。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|

| client_name | varchar(200) | 是 | - | 客户端名称 |
| client_authentication_methods | varchar(1000) | 是 | - | 客户端认证方式集合 |

### 3.5 `oauth2_authorization_consent`：授权同意表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| registered_client_id | varchar(100) | 是 | - | 关联客户端内部主键 `oauth2_registered_client.id` |
| principal_name | varchar(200) | 是 | - | 授权主体，用户场景为 `user_code` |

- 索引：`idx_consent_principal(principal_name)`。

### 3.6 `oauth2_authorization_record`：授权历史表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|

| client_name | varchar(200) | 否 | NULL | 客户端名称快照 |
| principal_name | varchar(200) | 是 | - | 授权主体 |
| granted_authorities | varchar(2000) | 是 | - | 已授予范围 |
| grant_type | varchar(100) | 否 | NULL | 授权模式 |

| trace_id | varchar(64) | 否 | NULL | 授权链路追踪 ID |

约束与索引：

### 3.7 `iam_client_policy`：客户端登录准入策略表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| id | bigint unsigned | 是 | 自增 | 主键 |
| client_id | varchar(100) | 是 | - | OAuth2 客户端标识 |
| allowed_roles | varchar(1000) | 否 | NULL | 允许登录的角色编码；空或 `*` 表示不限制 |
| allowed_tenant_types | varchar(500) | 否 | NULL | 允许的租户类型集合 |
| require_tenant | tinyint(1) | 是 | 1 | 是否要求用户选择有效租户 |
| status | tinyint(1) | 是 | 1 | 策略是否启用 |
| remark | varchar(500) | 否 | NULL | 备注 |
| 公共审计字段 | - | - | - | 创建人、创建时间、修改人、修改时间 |

约束与索引：

- 唯一键：`uk_client_policy_client(client_id)`。
- 策略校验失败必须拒绝签发 Token，不能降级放行。

### 3.8 `iam_login_attempt`：登录尝试表

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|:---:|---|---|
| id | bigint unsigned | 是 | 自增 | 主键 |
| username | varchar(100) | 是 | - | 用户提交的登录名 |
| user_code | varchar(64) | 否 | NULL | 能解析到用户时记录 |
| tenant_code | varchar(64) | 否 | NULL | 登录时选择的租户 |
| client_id | varchar(100) | 否 | NULL | 发起登录的客户端 |
| auth_type | varchar(30) | 是 | `password` | `password/social/device_code` 等 |
| success | tinyint(1) | 是 | 0 | 是否成功 |
| failure_reason | varchar(100) | 否 | NULL | `BAD_CREDENTIALS/LOCKED/DISABLED/RATE_LIMITED` |
| request_ip | varchar(64) | 否 | NULL | 来源 IP，兼容 IPv6 |
| user_agent | varchar(500) | 否 | NULL | User-Agent |
| trace_id | varchar(64) | 否 | NULL | 链路追踪 ID |
| attempt_time | datetime(3) | 是 | 当前时间 | 尝试时间 |
| locked_until | datetime(3) | 否 | NULL | 本次失败导致的锁定截止时间 |

约束与索引：

- 索引：`idx_login_username_time(username, attempt_time)`。
- 索引：`idx_login_ip_time(request_ip, attempt_time)`。

- 大数据量时按月分区或定期归档；实时失败计数优先放 Redis，本表保存审计证据。

### 3.11 `oauth2_authorization`：OAuth2 运行时授权表（P2 可选）

| authorized_scopes | varchar(1000) | 否 | 已授权 Scope |

| authorization_code_expires_at | datetime(3) | 否 | 授权码过期时间 |
| authorization_code_metadata | blob | 否 | 授权码元数据 |
| access_token_value | blob | 否 | Access Token 值，必须加密或只保存不可逆摘要 |

| access_token_metadata | blob | 否 | Access Token 元数据 |

## 八、核心关系与一致性规则

### 8.1 租户、商户和组织关系

```text
iam_tenant
  ├── iam_tenant_user ── user_code ──> sys_user
  ├── iam_merchant
  │     └── iam_merchant_user ── user_code ──> sys_user
  └── iam_org
        └── iam_org_user ── user_code ──> sys_user
```

一致性规则：

1. 商户和组织必须属于有效租户。
2. 商户成员、组织成员必须先是有效租户成员。
3. 组织绑定商户时，组织、商户必须属于同一租户。
4. 用户退出租户时，应先停用其商户成员、组织成员、租户角色和应用授权，不能只删除 `iam_tenant_user`。

### 8.2 RBAC 与资源关系

```text
sys_user_role
  └── sys_role
        ├── sys_role_permission ──> sys_permission
        │                             └── iam_permission_resource ──> iam_resource
        └── iam_role_data_scope ──> iam_data_scope
                                  └── iam_resource(DATA_OBJECT)
```

授权计算必须同时满足：

1. 当前租户、用户、角色分配均有效且未过期。
2. 角色和权限属于当前租户，或权限为 `__PLATFORM__` 公共权限。
3. 资源已启用，且来源对象仍然存在。
4. 数据范围只返回结构化过滤条件，由访问方使用白名单字段转换，禁止执行存储的 SQL。

### 8.3 门户可见性关系

```text
iam_application
  ├── iam_application_channel
  ├── iam_portal_menu ──> iam_portal_page
  └── iam_portal_workspace ──> iam_portal_workspace_item

iam_app_authorization
  └── tenant_code + app_code + channel_code
```

门户返回应用、渠道、菜单或页面前，必须同时检查对象状态、资源权限和应用授权。`iam_portal_user_preference` 只能改变排序和默认项，不能扩大可见范围。

### 8.4 开放平台准入关系

```text
iam_open_developer
  └── iam_open_application
        └── iam_open_app_client ── client_id ──> oauth2_registered_client
              └── iam_capability_subscription ──> iam_api_capability
                    ├── iam_capability_usage
                    └── iam_api_call_log
```

一次 API 调用至少验证：

1. OAuth2 客户端有效、密钥或 PKCE 校验通过。
2. 第三方应用、客户端映射、能力和订阅均有效。
3. 当前时间在订阅有效期内。
4. Token Scope 满足能力要求。
5. QPS、日配额和月配额均未超限。
6. 拒绝请求也写调用结果和聚合计数，但不记录敏感报文。

## 九、迁移与落地顺序

### 9.1 P0：先完成隔离正确性

1. 创建 `iam_tenant_db`，迁移并增强 `iam_tenant`、`iam_tenant_user`、`iam_org`。
2. 新建商户、商户成员和组织成员表。
3. 改造 `sys_role`、`sys_user_role`、`sys_permission` 的租户维度。
4. 将应用授权由 `app_id/channel_id` 改为 `app_code/channel_code`。
5. 建设统一资源和数据范围四张表。
6. 建设登录尝试、操作审计和能力调用聚合表。

### 9.2 P1：完成领域分库

1. 创建 `iam_portal_db`，迁移应用和渠道，新增菜单、页面、组件、工作台。
2. 创建 `iam_open_db`，迁移能力和订阅，新增开发者、第三方应用、审批和调用日志。
3. 建设租户配置和套餐三张表。
4. 通过双写、回填校验、切读和停止旧写完成迁移，禁止停机直接改库名。

### 9.3 P2：增强恢复与个性化

1. 按需要启用 `oauth2_authorization` 和 Spring Session JDBC 表。

3. 对审计、授权历史、调用日志和统计数据制定归档、分区与保留周期。
