## 2. 全局设计原则（红线）

1. **双库边界**：`iam_identity` = 身份权威（凭据/客户端/会话）；`iam_authorization` = 业务授权权威（RBAC/应用/能力）。**不跨库写对方权威数据，不共享库**。
2. **编码寻址**：跨库/跨服务一律以业务编码（`user_code` / `tenant_code`）逻辑引用，**不下放内部自增主键，不建 DB 外键**（可重入、可幂等）。
3. **单一权威**：凭据 → 认证中心；业务 RBAC / 权限 → 资源中心；应用目录 → 资源中心；OAuth2 客户端 → 认证中心。
4. **token sub = user_code**：令牌主体恒为业务用户编码；`grant_type` / `client_id` 是判定令牌类别的依据，**禁止由"本地查不到用户"反推**（V6.2 已去影子用户表）。
5. **密钥零落库**：渠道/应用密钥仅创建/重置一次性返回明文，各中心不落库。
6. **表驱动准入（三档）**：资源中心接口准入由 `iam_endpoint_policy` 驱动（启动扫描播种，admin/portal/third 三域；表外默认走认证档，未登记不再默认拒绝）；业务鉴权禁止在 SecurityFilterChain 写死规则——链层仅允许放行白名单（`/api/permitall/**`），见 §4.2。
7. **令牌类别≠业务角色**：不再产生 `ROLE_` 前缀令牌类别；authorities 注入业务角色码原样返回。

## 3. 认证中心开发规范（iam-authorization-server）

### 3.1 代码结构规划

```
net.xzh.iam.auth                       # 认证/协议模块（共享 Result 在 net.xzh.iam.common）
├── config/          # 基础设施：Jackson / MyBatis-Plus / Redis / AuthServerProperties
├── controller/      # **平铺**认证/协议端点：Login / Consent / DeviceActivate / Logout / UserInfo
├── entity/ / mapper/ / vo/   # MyBatis-Plus 三件套 + 视图对象
├── security/        # 安全层：AuthorizationServerConfig（3 条 FilterChain）+ authentication/repository/token/session/userdetails/web
└── service/         # 业务服务（含用户生命周期编排，见 §3.4）

> 原认证侧管理 REST（AdminUser/AdminClient/AdminSession/AdminRecord/AdminClientPolicy，`/api/admin/**`）
> 已移入资源中心 `controller/admin`（§4.1，包重构批次）；`remote/` 服务间调用随单服务合并退役（§5）。
```

### 3.2 端点规划

- **协议端点**（OAuth2/OIDC，`/oauth2/**`、`/.well-known/**`、`/userinfo`）由 `AuthorizationServerConfig` 统一管理，不归业务分包。
- **管理 API**（`/api/admin/**`）：管理面写读操作全部走此域，由管理前端（admin-web → admin-bff）以 `admin-app` 用户令牌访问；Bearer + `ADMIN_SERVICE_TOKEN`；控制器位于资源中心 `controller/admin`（§4.1，双域合并后同进程）。
- **认证/页面端点**（`controller/` 平铺）：登录页、同意页、登出、UserInfo。

### 3.3 远程调用与服务凭证规范

认证中心作为协调方调用资源中心时，必须使用 `ServiceTokenProvider` 的两类服务凭证（client_credentials，进程内按 TTL 缓存，401 自愈，禁止复用页面/用户令牌做服务间调用）：详见 §5 凭证矩阵。

### 3.4 用户生命周期事件边界（核心章节）

> 回答"删除/禁用/重置用户，谁来做"，确立**事件发布者 ≠ 数据所有者**：

| 动作 | 权威方 | 归属维度 |
|------|--------|---------|
| 删除 `sys_user`（身份/凭据） + 撤销会话 | 认证中心 | 本地事务（`iam_identity` + Redis） |
| 清理 `sys_user_role` / `iam_app_authorization` | 认证中心 | **本地直调** `RbacService` / `ApplicationService`（合并单服务；原跨服务 admin-m2m 链已退役），幂等 |
| 事件协调（触发级联清理） | **认证中心** | 唯一的"删除用户"事件发布点 |

**规则**：
1. 用户的**生命周期事件唯一产自认证中心**（身份删除 + 会话撤销在本地一事务内）。合并单服务后，清理授权数据与删除身份在同一进程内完成：`UserService` **本地直调** `RbacService` / `ApplicationService`，不再跨服务换令牌（原 `admin-m2m` 管理 M2M 凭证通道已退役）。
2. 级联清理为 **best-effort**：`cleanupRelatedDataSafely` 捕获本地异常只打日志，**不得**因清理失败回滚身份删除事务。
3. 凭证收敛（现状）：`/api/admin/**` 管理面以 `ADMIN_SERVICE_TOKEN` 把关，仅**管理员用户令牌**（业务角色含 `ADMIN`）可注入；服务令牌（client_credentials，含原 admin-m2m）一律只注入 `PORTAL_SERVICE_TOKEN`，无管理资格。原 `internal` 域远程内省通道已随合并退役。
4. 会话撤销（强制下线）放事务外执行（`kickOfflineSafely`），Redis 异常不得导致 DB 回滚。

**其它用户的写操作**（重置密码/禁用/改密）同样：本地权威事务 + 事务外会话撤销；仅删除涉及资源中心级联清理。

## 4. 资源中心开发规范（iam-resource-service）

### 4.1 代码结构规划

```
net.xzh.iam.resource                 # （共享 Result 在 net.xzh.iam.common）
├── config/                          # 安全 + 准入（唯一保留的初始化器）
│   ├── ResourceServerConfig         #   SecurityFilterChain（/api/** 全走 EndpointAdmissionManager；/api/permitall/** permitAll）
│   ├── EndpointAdmissionManager     #   三档准入路由器（表内强控制 / 表外认证档 / 链层放行）
│   ├── RbacAuthoritiesOpaqueTokenIntrospector  # RBAC 内省增强器（注入令牌类别）
│   ├── AuthServerProperties         #   authserver.* 配置（服务/门户/管理白名单）
│   └── EndpointPolicyScanInitializer#   启动扫描播种准入点（幂等）
├── controller/                      # **按能力域分包（核心约定，见 §4.2）**
│   ├── admin/                       #   管理端能力 /api/admin/**
│   ├── portal/                      #   门户端能力 /api/public/**
│   └── permitall/                   #   放行示例 /api/permitall/**（链层 permitAll，不入准入表）
├── entity/ / mapper/ / service/     # MyBatis-Plus 三件套 + 业务服务
```

### 4.2 controller 分包 ↔ 能力域 ↔ 准入档位（三档模型）

`EndpointPolicyService` 按 `net.xzh.iam.resource.controller.<leaf>.*` 推导能力域；**播种白名单仅 admin / portal / third 三域**：

| controller 分包 | 能力域 | 路径前缀 | 准入档位 | 客户端白名单闸门 |
|-----------------|--------|----------|----------|------------------|
| `admin` | admin | `/api/admin/**` | **入表** · `ADMIN_SERVICE_TOKEN`（管理服务凭证） | 无（凭证已够） |
| `portal` | portal | `/api/public/**` | **入表** · `PORTAL_SERVICE_TOKEN`（门户服务凭证） | `authserver.portal-client-ids`（默认 portal-app） |
| `third`（预留，暂无分包/端点） | third | — | **入表** · `AUTHENTICATED` | — |
| `permitall` | （不入表） | `/api/permitall/**` | **链层放行**：Security `requestMatchers("/api/permitall/**").permitAll()`（免令牌，不进规则表） | — |
| 其它分包 / 平铺控制器 | （不入表） | `/api/**` 表外 | **认证档**：持有效认证主体即放行（`OAuth2AuthenticatedPrincipal`，匿名令牌拒绝） | — |

- **三档准入**：① 链层放行（`/api/permitall/**`，免令牌）；② 表外认证档（`findRule == null` → 以认证主体判定，**不再 deny-by-default**）；③ 表内强控制（admin / portal / third 播种行 + portal 白名单闸门）。`internal` 域与硬规则、`other` / `capability` / `PERMIT_ALL` 表内取值均已随阶段 4 与能力域清理删除。
- **新端点三步走**：① 放对 `controller/<域>` 分包（admin/portal/third）；② 端点正常注解（`@RestController` + 映射）；③ 重启由 `EndpointPolicyScanInitializer` 自动播种，无需手写 SQL 或 Security 规则；域外新端点不入库、默认走认证档。coded 行随代码版本自动对齐（准入或域任一变化即更新）。
- **准入行维护**：管理 REST（列表/覆盖/重置/手工 rescan）已随准入管理页退役；启动扫描负责播种与失效行清理，存量数据调整走 migration SQL（§6）。历史 `override` 行仍随快照生效，但仅能经 SQL 修改。

### 4.3 管理写边界（controller/admin）

- **管理写操作归 admin 域**：凡"由管理动作触发的写副作用"，一律归 `controller/admin` 管理端能力，以 `ADMIN_SERVICE_TOKEN`（仅管理员令牌注入，原 admin-m2m 凭证注入通道已退役）把关。示例：删除用户联动清理 `AdminUserDataController`（`DELETE /api/admin/users/{userCode}/data`）。
- （已退役）原 `controller/internal` 只读内省与硬规则边界随阶段 4 删除，历史说明见 `docs/对外接口说明.md` §2.4。

### 4.4 内省注入规则（令牌类别判定，RbacAuthoritiesOpaqueTokenIntrospector）

按 `grant_type` / `client_id` 判定，顺序判定：

| 令牌来源 | 注入 | 用途 |
|---------|------|------|
| client_credentials 服务令牌（一律；原 admin-m2m 管理通道已退役） | `PORTAL_SERVICE_TOKEN` | M2M 服务令牌，无管理资格 |
| portal-app 签发的用户令牌 | 业务 RBAC + `PORTAL_SERVICE_TOKEN` | portal 域门票 |
| 其它用户令牌（sub=user_code，业务角色含 `ADMIN`） | 业务 RBAC + `ADMIN_SERVICE_TOKEN` | 管理端（管理台） |

## 5. 服务间调用与凭证矩阵（通吃两端）

> **现状批注（合并单服务后）**：本节原「跨服务换证矩阵」已**全部退役**——内省改为同进程 Redis 本地内省
> （`RbacAuthoritiesOpaqueTokenIntrospector` 直接委托 `RedisOpaqueTokenIntrospector`，不再 HTTP 换证/自回环），
> 删用户联动清理为本地直调；`resource-server`、`admin-m2m` 换证客户端及其 yml 凭证配置均已删除。
> 下表保留作历史规范说明。

| 场景 | 调用方 | 换证客户端（client_credentials） | 资源中心注入 | 目标 |
|------|--------|--------------------------------|--------------|------|
| 角色内省（登录取权/签发准入） | 认证中心 | `resource-server` | `PORTAL_SERVICE_TOKEN` | `GET /api/internal/user/{userCode}/roles` |
| 删除用户联动清理 | 认证中心 | `admin-m2m` | `ADMIN_SERVICE_TOKEN` | `DELETE /api/admin/users/{userCode}/data` |
| 目录/内省 | 资源中心 / 各端 | `resource-server` | — | `/oauth2/introspect`、`/api/directory/clients` |

**规则**：
- **（已退役）**原认证中心侧凭证配置 `service-token-client-id` / `admin-service-token-client-id` 及独立缓存已删除。
- **（已退役）**原资源中心侧白名单 `admin-m2m-client-ids` 已删除；`portal-client-ids`、`service-client-ids` 仍生效（见 §4.4）。
- **新增跨进程调用**：合并单服务后**默认禁止**任何服务间 HTTP 调用；确有跨进程需求须先评审，不得复活已退役的换证矩阵。

## 6. 数据库与迁移规范

- **基线脚本**：`iam_identity.sql`、`iam_authorization.sql`（各自模块 `src/main/resources/`），是全新环境建库的唯一来源，随新表/新种子同步更新。
- **迁移脚本**：`src/main/resources/migration/V6.x__*.sql` 为**存量库升级的唯一执行途径**（由 DBA/升级账号手动执行，可持有跨库权限；不接入自动迁移框架）。**应用启动不再执行任何 DDL / 破坏性迁移 / 种子初始化**（初始化器已拆除），业务数据以基线 SQL + 迁移脚本 + 管理端 API 为准。
- **例外**：`EndpointPolicyScanInitializer`（资源中心）是唯一保留的运行期初始化器——它不产生"数据"，而是把活代码的 controller 分包/映射推导成 `iam_endpoint_policy` 的 coded 准入行（端点目录与代码同步依赖它）。
- **约定**：新表 = 基线 SQL（新库）+ migration 脚本（存量库）；不新增种子/迁移初始化器。
- **命名**：表名 `iam_` 前缀；业务编码列统一：`user_code`、`tenant_code`、`client_id`；时间戳 `create_time/update_time`；软删 `deleted`；（资源中心例外：`iam_endpoint_policy` / `sys_permission` 用 `status` 启停、无逻辑删）。

## 7. 命名与编码规范

- Java 包一律 `net.xzh.<module>` 下按 `common/config/controller(分包)/entity/mapper/remote/service/vo/security` 组织；controller **按能力域分包**（见 §4.2），禁止按 HTTP 动词或按表堆包。
- 注释使用类级 javadoc：先写"业务定位 + 边界/安全约束 + 上下游 + 版本决策（V6.x/Dx）"。参考 `InternalRoleController` / `AdminUserDataController`。
- 日志：模块前缀 tag（`[admin]` / `[EndpointPolicy]` / `[UserData]` 等）+ 关键字段（userCode）便于检索；敏感信息（令牌/密钥/明文密码）一律禁止落日志。
- 统一响应：`Result`（`code/msg/data`）；OAuth2 协议端点除外。
- 幂等与 self-heal：远程调用带 TTL 缓存 + 401 强制刷新重试；跨库级联 best-effort。
