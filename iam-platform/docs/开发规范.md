## 2. 全局设计原则（红线）

1. **双库边界**：`iam_identity` = 身份权威（凭据/客户端/会话）；`iam_authorization` = 业务授权权威（RBAC/应用/能力）。**不跨库写对方权威数据，不共享库**。
2. **编码寻址**：跨库/跨服务一律以业务编码（`user_code` / `tenant_code`）逻辑引用，**不下放内部自增主键，不建 DB 外键**（可重入、可幂等）。
3. **单一权威**：凭据 → 认证中心；业务 RBAC / 权限 → 资源中心；应用目录 → 资源中心；OAuth2 客户端 → 认证中心。
4. **token sub = user_code**：令牌主体恒为业务用户编码；`grant_type` / `client_id` 是判定令牌类别的依据，**禁止由"本地查不到用户"反推**（V6.2 已去影子用户表）。
5. **密钥零落库**：渠道/应用密钥仅创建/重置一次性返回明文，各中心不落库。
6. **表驱动准入**：资源中心接口准入由 `iam_endpoint_policy` 驱动（启动扫描播种 + 管理端覆盖，未登记默认拒绝），禁止在 SecurityFilterChain 写死业务路径规则。
7. **令牌类别≠业务角色**：不再产生 `ROLE_` 前缀令牌类别；authorities 注入业务角色码原样返回。

## 3. 认证中心开发规范（iam-authorization-server）

### 3.1 代码结构规划

```
net.xzh.authserver
├── common/          # 通用：Result 统一响应封装
├── config/          # 基础设施：Jackson / MyBatis-Plus / Redis / AuthServerProperties / DataInitializer
├── controller/
│   ├── api/         # 管理 REST API（/api/admin/**，Bearer + ADMIN_SERVICE_TOKEN）
│   │   ├── AdminUserApiController        #   用户域（CRUD/启用禁用/重置密码/踢会话）
│   │   ├── AdminClientApiController      #   客户端域（CRUD/重置密钥）
│   │   ├── AdminSessionApiController     #   会话域（在线/层级视图/踢下线）
│   │   ├── AdminRecordApiController      #   授权记录域
│   │   ├── AdminClientPolicyApiController#   令牌签发准入策略（iam_client_policy）
│   │   └── AdminTenantApiController      #   租户域（iam_tenant）
│   └── auth/        # 认证/协议端点：Login / Consent / DeviceActivate / Logout / UserInfo
├── entity/ / mapper/ / vo/   # MyBatis-Plus 三件套 + 视图对象
├── remote/          # 远程服务间调用
│   ├── ServiceTokenProvider      # 服务令牌供给（两类凭证，独立缓存）
│   ├── RemoteRoleService         # 资源中心角色内省（/api/internal/user/{userCode}/roles，30s TTL）
│   └── InternalUserDataClient    # 用户删除联动清理（管理 M2M，/api/admin/users/{userCode}/data）
├── security/        # 安全层：AuthorizationServerConfig（3 条 FilterChain）+ authentication/repository/token/session/userdetails/web
└── service/         # 业务服务（含用户生命周期编排，见 §3.4）
```

### 3.2 端点规划

- **协议端点**（OAuth2/OIDC，`/oauth2/**`、`/.well-known/**`、`/userinfo`）由 `AuthorizationServerConfig` 统一管理，不归业务分包。
- **管理 API**（`/api/admin/**`，`controller/api`）：管理面写读操作全部走此域，最终由管理前端（admin-web → admin-service）以 `admin-app` 用户令牌访问；Bearer + `ADMIN_SERVICE_TOKEN`。
- **认证/页面端点**（`controller/auth`）：登录页、同意页、登出、UserInfo。

### 3.3 远程调用与服务凭证规范

认证中心作为协调方调用资源中心时，必须使用 `ServiceTokenProvider` 的两类服务凭证（client_credentials，进程内按 TTL 缓存，401 自愈，禁止复用页面/用户令牌做服务间调用）：详见 §5 凭证矩阵。

### 3.4 用户生命周期事件边界（核心章节）

> 回答"删除/禁用/重置用户，谁来做"，确立**事件发布者 ≠ 数据所有者**：

| 动作 | 权威方 | 归属维度 |
|------|--------|---------|
| 删除 `sys_user`（身份/凭据） + 撤销会话 | 认证中心 | 本地事务（`iam_identity` + Redis） |
| 清理 `sys_user_role` / `iam_app_authorization` | 资源中心 | 资源中心能力域（`/api/admin/users/{userCode}/data`，幂等） |
| 事件协调（触发级联清理） | **认证中心** | 唯一的"删除用户"事件发布点 |

**规则**：
1. 用户的**生命周期事件唯一产自认证中心**（身份删除 + 会话撤销在本地一事务内，无法由他人代发），因此认证中心是事件协调点；但**清理授权数据的动作本身属于资源中心能力域**，认证中心不越权直接操作资源中心数据，而是以**管理 M2M 服务凭证**（`admin-m2m`）调用其管理端能力。
2. 级联清理为 **best-effort**：`cleanupRemoteDataSafely` 捕获远程异常只打日志，**不得**因资源中心不可达回滚身份删除事务。
3. 凭证与域双收敛：内部只读走 `internal` 域（`PORTAL_SERVICE_TOKEN`），管理写走 `admin` 域（`ADMIN_SERVICE_TOKEN`，经 admin-m2m 注入）。**禁止**把管理写塞进 `controller/internal`。
4. 会话撤销（强制下线）放事务外执行（`kickOfflineSafely`），Redis 异常不得导致 DB 回滚。

**其它用户的写操作**（重置密码/禁用/改密）同样：本地权威事务 + 事务外会话撤销；仅删除涉及资源中心级联清理。

## 4. 资源中心开发规范（iam-resource-service）

### 4.1 代码结构规划

```
net.xzh.resource
├── common/                          # Result / 业务枚举
├── config/                          # 安全 + 准入 + 初始化
│   ├── ResourceServerConfig         #   SecurityFilterChain（./api/** 全走 EndpointAdmissionManager）
│   ├── EndpointAdmissionManager     #   表驱动准入路由器
│   ├── RbacAuthoritiesOpaqueTokenIntrospector  # RBAC 内省增强器（注入令牌类别）
│   ├── AuthServerProperties         #   authserver.* 配置（服务/门户/管理 M2M 白名单）
│   ├── EndpointPolicyScanInitializer#   启动扫描播种准入点（幂等）
│   └── CapabilitySchemaInitializer  #   能力表结构 + 种子（幂等）
├── controller/                      # **按能力域分包（核心约定，见 §4.2）**
│   ├── admin/                       #   管理端能力 /api/admin/**
│   ├── portal/                      #   门户端能力 /api/public/**
│   ├── capability/                  #   开放能力 /api/capability/**
│   ├── internal/                    #   服务间只读内省（对标内省接口）
│   └── permitall/                   #   不需要权限的接口示例（归 other 域，PERMIT_ALL）
├── entity/ / mapper/ / service/     # MyBatis-Plus 三件套 + 业务服务
```

### 4.2 controller 分包 ↔ 能力域 ↔ 默认准入（表驱动匹配）

`EndpointPolicyService` 按 `net.xzh.resource.controller.<leaf>.*` 推导能力域与默认准入：

| controller 分包 | 能力域 | 路径前缀 | 默认准入（coded） | 客户端白名单闸门 |
|-----------------|--------|----------|-------------------|------------------|
| `admin` | admin | `/api/admin/**` | `ADMIN_SERVICE_TOKEN`（管理服务凭证） | 无（凭证已够） |
| `portal` | portal | `/api/public/**` | `PORTAL_SERVICE_TOKEN`（门户服务凭证） | `authserver.portal-client-ids`（默认 portal-app） |
| `capability` | capability | `/api/capability/**` | `CAPABILITY`（能力订阅校验） | — |
| `internal` | internal | `/api/internal/**` | **硬规则（不进规则表）**：仅认证中心 M2M（`resource-server`），见 `EndpointAdmissionManager` | — |
| `permitall` | other | `/api/permitall/**` | `PERMIT_ALL`（放行，仅测试示例） | — |
| （其它） | other | — | `AUTHENTICATED` | — |

- `internal` 域不参与 `iam_endpoint_policy` 播种与管理（`EndpointPolicyService.rescan` 整域跳过 + 清理残留行），管理端不可见、不可 override；裁决在 `EndpointAdmissionManager.check` 前置分支按 `/api/internal/**` 前缀硬编码。
- **新端点三步走**：① 放对 `controller/<域>` 分包；② 端点正常注解（`@RestController` + 映射）；③ 重启由 `EndpointPolicyScanInitializer` 自动播种，无需手写 SQL 或 Security 规则。coded 行随代码版本自动对齐（准入或域任一变化即更新），override 行永远不动。
- **管理员覆盖**：管理端以 `PUT /api/admin/endpoint-policies/{id}` 可将某行置 override（改准入/停用）；`DELETE` 重置回 coded。`internal` 域行不存在于此管理面。
- 未登记路径 = 默认拒绝（deny-by-default）。

### 4.3 internal（只读内省）与 管理写（controller/admin + 管理 M2M）边界

- `controller/internal` **对标认证中心内省接口（/oauth2/introspect）**，仅承载**只读**能力（当前仅 `InternalRoleController` 角色内省），鉴权为**硬规则**：`PORTAL_SERVICE_TOKEN` 且 `client_id == resource-server`（认证中心 M2M），既不经规则表也不经 `service-client-ids` 配置。
- **管理写操作禁止入 internal**：凡"由管理动作触发的写副作用"，一律归 `controller/admin` 管理端能力，以 `ADMIN_SERVICE_TOKEN`（经管理 M2M 凭证或管理员令牌注入）把关。示例：删除用户联动清理 `AdminUserDataController`（`DELETE /api/admin/users/{userCode}/data`）。

### 4.4 内省注入规则（令牌类别判定，RbacAuthoritiesOpaqueTokenIntrospector）

按 `grant_type` / `client_id` 判定，顺序判定：

| 令牌来源 | 注入 | 用途 |
|---------|------|------|
| client_credentials 服务令牌 且 client_id ∉ admin-m2m 白名单 | `PORTAL_SERVICE_TOKEN` | portal M2M（internal 域另有 `resource-server` 硬过滤） |
| client_credentials 服务令牌 且 client_id ∈ `admin-m2m-client-ids`（默认 admin-m2m） | `ADMIN_SERVICE_TOKEN` | /api/admin/** 管理写 |
| portal-app 签发的用户令牌 | 业务 RBAC + `PORTAL_SERVICE_TOKEN` | portal 域门票 |
| 其它用户令牌（sub=user_code，业务角色含 `ADMIN`） | 业务 RBAC + `ADMIN_SERVICE_TOKEN` | 管理端（管理台） |

## 5. 服务间调用与凭证矩阵（通吃两端）

| 场景 | 调用方 | 换证客户端（client_credentials） | 资源中心注入 | 目标 |
|------|--------|--------------------------------|--------------|------|
| 角色内省（登录取权/签发准入） | 认证中心 | `resource-server` | `PORTAL_SERVICE_TOKEN` | `GET /api/internal/user/{userCode}/roles` |
| 删除用户联动清理 | 认证中心 | `admin-m2m` | `ADMIN_SERVICE_TOKEN` | `DELETE /api/admin/users/{userCode}/data` |
| 目录/内省 | 资源中心 / 各端 | `resource-server` | — | `/oauth2/introspect`、`/api/directory/clients` |

**规则**：
- 认证中心侧配置：`service-token-client-id: resource-server`（门户凭证）、`admin-service-token-client-id: admin-m2m`（管理 M2M 凭证）；各自独立缓存 + `invalidate*`。
- 资源中心侧白名单：`portal-client-ids`（门户客户端）、`admin-m2m-client-ids`（管理 M2M → ADMIN_SERVICE_TOKEN）；`service-client-ids` 与 internal 域**解耦**——internal 为硬规则（仅 `resource-server` 可调），不受该配置影响，该项仅作服务令牌判定兜底。
- **新增服务间写调用**：若认证中心（或其它的系统对资源中心）需要新管理写，一律新增/复用 admin 域端点 + 管理 M2M 凭证，**禁止**扩 internal 域写能力，也禁止用门户服务凭证干管理写。

## 6. 数据库与迁移规范

- **基线脚本**：`iam_identity.sql`、`iam_authorization.sql`（各自模块 `src/main/resources/`），是全新环境建库的唯一来源，随新表/新种子同步更新。
- **迁移脚本**：`src/main/resources/migration/V6.x__*.sql` 为**存量库参考/审计脚本**（幂等），**不接入自动迁移框架**；对应的运行时兜底由各 `*Initializer`（ApplicationRunner，幂等）负责，例如：
  - `DataInitializer`（认证中心）：客户端兜底补建（admin-app / resource-server / admin-m2m 等）
  - `CapabilitySchemaInitializer` / `EndpointPolicyScanInitializer`（资源中心）：建表与准入行播种
  - `ShadowUserMigrationInitializer` / `CrossDbCodeMigrationInitializer`：历史数据清洗
- **约定**：新表 = 基线 SQL + migration 参考脚本 + 幂等 Initializer（如需运行期兜底）；纯 SQL 可幂等则直接进 migration。
- **命名**：表名 `iam_` 前缀；业务编码列统一：`user_code`、`tenant_code`、`client_id`、`capability_code`；时间戳 `create_time/update_time`；软删 `deleted`；（资源中心例外：`iam_endpoint_policy` 用 `status` 启停、无逻辑删）。

## 7. 命名与编码规范

- Java 包一律 `net.xzh.<module>` 下按 `common/config/controller(分包)/entity/mapper/remote/service/vo/security` 组织；controller **按能力域分包**（见 §4.2），禁止按 HTTP 动词或按表堆包。
- 注释使用类级 javadoc：先写"业务定位 + 边界/安全约束 + 上下游 + 版本决策（V6.x/Dx）"。参考 `InternalRoleController` / `AdminUserDataController`。
- 日志：模块前缀 tag（`[admin]` / `[internal]` / `[UserData]` 等）+ 关键字段（userCode）便于检索；敏感信息（令牌/密钥/明文密码）一律禁止落日志。
- 统一响应：`Result`（`code/msg/data`）；OAuth2 协议端点除外。
- 幂等与 self-heal：远程调用带 TTL 缓存 + 401 强制刷新重试；跨库级联 best-effort。
