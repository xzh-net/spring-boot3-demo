# 编码规范

平台唯一的编码与结构规范入口。**包结构为硬性要求**，评审/合入前须逐条核对。

---

## 一、包结构（硬性要求）

### 1.1 服务端模块 `server/iam-authorization-server`

基础包 `net.xzh.iam`，**只允许三个一级域包 + 一个主启动类**：

```text
net.xzh.iam
├── AuthorizationServerApplication.java   ← 根包【唯一允许的类】（Spring Boot 主启动类，组件扫描锚点）
├── common/          公共基建：Result / GlobalExceptionHandler / MybatisPlusConfig
│
├── auth/            【协议域】OAuth2·OIDC·登录会话（谁是谁）
│   ├── config/           基础设施配置（Jackson / MyBatis-Plus / Redis）
│   ├── controller/       平铺协议端点（Login / Consent / Logout / UserInfo / DeviceActivate）
│   ├── entity/  mapper/  vo/       MyBatis-Plus 三件套 + 视图对象
│   ├── service/          用户/客户端/会话编排
│   └── security/         安全层
│       ├── AuthorizationServerConfig.java    3 条 FilterChain 装配
│       ├── authentication/{client,grant}/    客户端认证 / 自定义 grant provider
│       ├── repository/    JdbcRegisteredClientRepository / RedisOAuth2AuthorizationService
│       ├── token/         RedisOpaqueTokenIntrospector 等令牌组件
│       ├── session/       RedisSessionRegistry
│       ├── userdetails/   PlatformUserDetailsService（唯一 IdP）
│       └── web/           过滤器与上下文（AuthorizeIssuanceFilter / CompositeSecurityContextRepository）
│
└── resource/        【业务域】API 与准入（能做什么）
    ├── config/           ResourceServerConfig / EndpointAdmissionManager / 自省器 / 扫描初始化器
    ├── controller/
    │   ├── admin/         /admin/**  三域管理 API（11 个 Controller）
    │   ├── portal/        /biz/** 门户 API
    │   └── permitall/     /permitall/** 免令牌探测
    ├── entity/  mapper/  vo/       三件套 + 视图对象
    └── service/          RbacService / ScopeService / EndpointPolicyService / ApplicationService …
```

### 1.2 结构红线（违反即驳回）

| # | 规则 |
|---|---|
| 1 | 根包 `net.xzh.iam` **只放 `AuthorizationServerApplication`**，其余类必须归入 `common` / `auth` / `resource` 之一 |
| 2 | **controller 按能力域分包**（`auth.controller` 平铺协议端点；`resource.controller.{admin,biz,permitall}`）；**禁止**按 HTTP 动词（get/post）或按表名堆包 |
| 3 | **domain 包不可越界**：`auth` 不得 import `resource.controller.*`，`resource` 不得反向依赖 `auth.security.*` 的内部实现（跨域协作只经 `common` 与公开 service 接口） |
| 4 | 新增表 = **entity + mapper 三件套**齐备；**不建 DB 外键**，跨实体以业务编码逻辑引用 |
| 5 | **禁止 `remote/` / `client/` 等服务间调用包**——单服务进程内直调，不得复活已退役的 HTTP 换证 |
| 6 | 公共基建只进 `common`（Result / 异常 / 配置基类），**禁止**放领域类 |
| 7 | 安全装配集中在 `auth.security.AuthorizationServerConfig` 与 `resource.config.ResourceServerConfig`，**禁止**在别处新建 `SecurityFilterChain` |

### 1.3 其它模块

| 模块 | 结构要求 |
|---|---|
| `bff/*` | `controller` + `service`，无 entity/mapper（**无库**，只做 OAuth2 Client 与透传） |
| `web/*` | 纯静态：`*.html` + `common.js`（鉴权/菜单/请求封装统一收口），**无构建链、无框架** |
| `client/*` | 零依赖 Node demo，每目录 `server.js` + `README.md` |

## 二、全局设计原则（红线）

1. **单库单服务**：唯一库 `iam`、唯一服务端 `:9000`；不建第二库、不引服务间 HTTP 调用。
2. **编码寻址**：跨表/跨实体一律业务编码（`user_code` / `client_id` / `org_code` / `app_code`），
   **不下放内部自增主键、不建 DB 外键**（可重入、可幂等）。
3. **单一权威**：凭据 → `sys_user`；业务角色权限 → `sys_role`/`sys_permission`；
   客户端注册 → `oauth2_registered_client`；端点准入 → `iam_endpoint_policy`。**不建平行第二权威**。
4. **令牌 `sub` = `user_code`**：判定令牌类别只看 `grant_type` / `client_id`，
   **禁止**由「本地查不到用户」反推；无影子用户表。
5. **fail-closed**：签发准入、自省注入、端点准入三层任一缺口即拒绝；**禁止**「猜一个默认放行」。
6. **表驱动准入**：业务鉴权禁止写死在 `SecurityFilterChain`；链层只允许放行白名单 `/permitall/**`。
7. **密钥零落库**：客户端明文密钥仅创建/重置一次性返回，代码与日志不留明文。
8. **权限码是稳定标识**：`sys_permission.code` 一经发布**不可改名**（被 `required_authority`
   字符串引用，改名会静默失联）；只能停用后新建。

## 三、命名规范

| 项 | 规范 |
|---|---|
| 表名 | 业务表 `iam_` 前缀；身份/协议保留 `sys_` / `oauth2_` 惯例名 |
| 列名 | 业务编码统一 `user_code`、`client_id`、`org_code`；时间戳 `create_time`/`update_time` |
| 软删 | 一般表用 `deleted`；`sys_permission`、`iam_endpoint_policy` 用 `status` 启停（无逻辑删） |
| 权限码 | `资源:动作` 小写冒号风格（`user:read`、`policy:write`），域前缀标在 `remark`（`【管理端】`/`【门户】`） |
| scope 码 | `{域}.{用途}`（`admin.full` / `portal.profile` / `third.profile`），域由前缀自表达 |
| 常量 | 全大写下划线；**禁止**复活已退役常量（`*_SERVICE_TOKEN`、`*_client_ids`） |
| 类名 | 领域后缀（`*Service` / `*Controller` / `*Repository` / `*Config`）；IdP 类名不带业务端前缀（用 `Platform*` 不用 `Portal*`） |
| 日志 tag | `[模块]` 前缀 + 关键字段（如 `[Admission]`、`[Introspect]`、`[签发准入]`），便于检索 |
| 响应体 | 统一 `Result{code,msg,data,timestamp}`；OAuth2 协议端点除外（RFC 6749 错误格式） |

## 四、编码约定

- **注释**：类级 javadoc 写「业务定位 + 边界/安全约束 + 上下游 + 关键取舍」；
  已退役机制用一句话标注退役原因与接替者（勿留大段死代码注释）。
- **日志**：敏感信息（令牌 / 密钥 / 明文密码）**禁止**落日志；准入决策必须打可审计日志
  （`[签发准入] 拒绝签发... 客户端=x, 用户=y`、`[Admission] path → authority = 结果`）。
- **事务**：本地事务管业务；Redis 操作（会话撤销、缓存刷新）放事务外，异常只记日志不回滚 DB。
- **幂等**：删除/清理由调用方保证可重入；级联清理 best-effort，**不得**因清理失败回滚主事务。
- **异常**：对外统一由 `GlobalExceptionHandler` 转 `Result`；协议端点交由 SAS 处理（勿自行包装）。
- **校验**：写接口入参必填项显式校验并抛 `IllegalArgumentException`，文案含具体字段值。

## 五、数据库与迁移规范

- **基线**：`sql/iam.sql`（单库 `iam` 合并基线，16 表）——**全新环境建库唯一来源**，随新表/新种子同步更新。
- **迁移**：`sql/migration/V6.x__*.sql` —— **存量库升级唯一途径**，由 DBA 手动执行；
  **应用启动不执行任何 DDL / 破坏性迁移 / 种子初始化**（初始化器已拆除）。
- **唯一例外**：`EndpointPolicyScanInitializer`（启动扫描）——它不产生业务数据，
  只把活代码的 controller 分包推导成 `iam_endpoint_policy` 的补缺行；**精确权限码权威始终在种子，扫描不回写、不剪除**。
- **约定**：新表 = 基线 SQL（新库）+ migration 脚本（存量库）；**不新增种子/迁移初始化器**。
- **字典只读**：`sys_scope`、`sys_scope_permission`、`iam_endpoint_policy` 的写入只走种子与扫描，
  **不提供页面写入口**（避免页面与种子双演进路径）。

## 六、禁止事项（黑名单）

| 禁止 | 原因 |
|---|---|
| 新建 `SecurityFilterChain` 除那 3 条外 | 准入规则必须走表驱动 |
| 在链层写死业务鉴权规则 | 违反表驱动准入 |
| 复活服务间 HTTP 调用 / 换证客户端（`resource-server`、`admin-m2m`） | 单服务进程内直调，凭证治理无消费方 |
| 恢复客户端白名单配置（`admin-client-ids` 等） | 由双维交集承担客户端隔离 |
| 引入粗档常量（`*_SERVICE_TOKEN`）作准入要求 | 多态软关联字段 → 静默死行 |
| Access Token 改为 JWT | 会破坏 Redis 内省模型 |
| 用 `user_label` 之类标签列做授权判定 | 授权只认 `sys_role` / `sys_permission` |
| 新增授权码客户端不开 PKCE | 认证中心 `requireProofKey=true` 会拒绝无 `code_challenge` 的授权请求；`ClientService.validate` 已强制（`authorizationGrantTypes` 含 `authorization_code` → `requireProofKey` 必须为 true），页面勾选「授权码」时 PKCE 联动锁定 |
| 重命名已发布的 `sys_permission.code` | 被 `required_authority` 字符串引用，改名静默失联 |
| 启动期跑 DDL / 重跑基线 | 基线 DROP 全表；迁移手动执行 |
| 把跨库历史概念（`iam_identity` / `iam_authorization` 双库）写进新代码 | 已合并单库 `iam` |
