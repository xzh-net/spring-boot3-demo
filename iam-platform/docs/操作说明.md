# 操作说明

日常启停、初始化、验证与排障。适用于当前单服务形态（`:9000` 服务端 + `:8085/:8001` 管理后台）。

---

## 一、环境前置

| 依赖 | 地址 | 用途 |
|---|---|---|
| MySQL 8 | `192.168.31.161:3306`，库 `iam` | 业务数据 |
| Redis | `192.168.31.161:6379` db1 | 会话 / 令牌运行时 |
| JDK 17 | `C:\Program Files\Java\jdk-17` | Java 服务 |
| Maven 3.6 | `D:\tools\apache-maven-3.6.3` | 构建 |
| Node.js | — | 静态前端（零依赖） |

连接地址改：`server/iam-authorization-server/src/main/resources/application-{profile}.yml`

```yaml
spring.datasource.url: jdbc:mysql://<host>:3306/iam?...
spring.data.redis.host: <host>
```

## 二、数据库初始化

### 全新建库（会 DROP 重建，勿在存量库执行）

```bash
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS iam DEFAULT CHARSET utf8mb4"
mysql -u root -p iam < sql/iam.sql
```

### 存量库升级

```bash
mysql -u root -p iam < sql/migration/V6.x__*.sql    # 按版本号顺序手动执行
```

> 不接 Flyway/Liquibase，迁移由 DBA/升级账号手动执行。**基线会 DROP 全表，存量库绝不可重跑基线。**

## 三、启停

### 一键（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File .\start-all.ps1            # 启动核心 5 个
powershell -ExecutionPolicy Bypass -File .\start-all.ps1 -Stop       # 全停
powershell -ExecutionPolicy Bypass -File .\start-all.ps1 -SkipMvnBuild  # 跳过预编译
```

启动：`authorization-server:9000`、`admin-bff:8085`、`portal-bff:8080`、`admin-web:8001`、`portal-web:8000`

### 计划任务（开发环境常驻）

| 任务名 | 服务 |
|---|---|
| `iam9000` | 服务端（jar 直启，日志 `Temp\opencode\boot9000.log`） |
| `iam8085` | 管理 BFF |
| `iam8001` | 管理前端 |

```powershell
Start-ScheduledTask iam9000; Start-ScheduledTask iam8085; Start-ScheduledTask iam8001
Stop-ScheduledTask  iam9000; Stop-ScheduledTask  iam8085; Stop-ScheduledTask  iam8001
```

### ⚠️ 启动顺序硬约束

**必须先 9000 后 8085。** BFF 启动时要拉 `http://localhost:9000/.well-known/openid-configuration`，
9000 未就绪会 `Connection refused` 直接退出（日志表现为 `Unable to resolve Configuration with the provided Issuer`）。

单独重启 9000 后，8085 无需重启（OIDC 端点在运行期解析）。

## 五、排障

### 1. DB/Redis 连不上（authorize 500 / 登录超时）

```
CommunicationsException: Connection timed out ... jdbc:mysql://<host>:3306/iam
RedisConnectionException: Unable to connect to <host>:6379
```
**原因**：宿主机 IP 变更（如本机从热点切到路由），或对端机器未开机。
**处理**：确认宿主机 IP → 改 `application-{profile}.yml` 的 datasource/redis → 重新打包重启：

```powershell
# 计划任务 jar 直启，必须重新打包
cd server\iam-authorization-server
mvn -q clean package -DskipTests
```

> 若通过计划任务且**改了模块路径**，还需更新任务参数：
> `(Get-ScheduledTask iam9000).Actions[0].Arguments` 里的 jar 路径。

### 2. SQL 直改 `oauth2_registered_client` 后权限异常（403 / invalid_client）

**原因**：`JdbcRegisteredClientRepository` 是 **JDBC + Redis 双层缓存**（key `oauth2:client:id:*` / `oauth2:client:cid:*`，TTL 1 小时）。绕过 `ClientService` 的 SQL 直写**不会失效缓存**，自省仍读到旧 `scopes`/`secret`。

**处理**：清缓存 key（Redis db1）：

```
DEL oauth2:client:id:2  oauth2:client:cid:admin-app    # 按实际 key
# 或工具: java -cp <jedis>; RedisClean.java
```

经「客户端管理」页编辑则自动失效缓存，无需手动清。

### 3. scopes 被摘后连管理端 API 都 403（死锁）

**原因**：`client:write` 等码同样经双维交集注入 → 摘掉 `admin.full` 后管理端自身也失去 `client:write`，**无法再用 API 还原**。

**处理**：SQL 直写恢复 `scopes` → 清第 2 条的 Redis 缓存。这是 fail-closed 的正常表现，非缺陷。

### 4. `admin-app` 密钥 `invalid_client`

DB 中 `admin-app.client_secret` 与实际不符（如重置密钥后未同步）。

```sql
UPDATE oauth2_registered_client
SET client_secret='$2a$10$ov3NUrdkAHujSRdGbDZF6O9h2cjZq4Zl17fL3TA5Nhs94mE/PmH8e'  -- =123456
WHERE client_id='admin-app';
```
随后清缓存（第 2 条）。

> ⚠️ **PowerShell 坑**：含 `$2a$` 的 BCrypt 串在命令行里会被当变量插值吃掉，必须写进 `.sql` 文件用工具执行。

### 5. 端点 403 但令牌码看似齐全

按序检查：
1. `iam_endpoint_policy` 该端点的 `required_authority` 是不是要求的码（`status` 是否被停用）
2. 令牌自省日志 `[Introspect] 用户令牌双维裁决` 中 `scopeCodes` / `交集注入` —— 客户端 scope 是否覆盖
3. 是否落在**认证档**（控制器不在 `controller.admin|portal|third` 包下 → 不入表）

### 6. 新加了端点但没进准入表

控制器包路径不对（`resolveDomain` 返回 null → 不入库）。移到三域包之一，重启触发扫描。

## 六、运维要点

### 新增一个受管控接口

```text
① sql/iam.sql: sys_permission 加权限码（remark 带【管理端】/【门户】前缀），若为新码
② sql/iam.sql: 按需绑 sys_role_permission / sys_scope_permission
③ sql/iam.sql: iam_endpoint_policy 加端点行，required_authority 写入该码
④ 重载基线到库 + 重启服务
```
> 控制器方法必须位于 `controller.admin|portal|third` 包下。

### 修改字典（scope / 端点准入）

两者**页面均只读**，一律改 `sql/iam.sql` 后重载。`oauth2_registered_client.scopes`、
角色绑码可直接走页面。

### 依赖顺序备忘

```
MySQL + Redis → 9000 → 8085 → 8001 （8001 依赖 8085 代理；8080/8000 门户按需）
```
