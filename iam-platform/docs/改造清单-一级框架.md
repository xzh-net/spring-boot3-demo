# IAM 平台改造清单 · 一级（框架问题与缺陷 · 优先推进）

> 版本：V1.0（2026-08-16）。由原 `docs/改造清单.md`（V0.3）逐项核对后拆分重组，原清单已删除。
> 一级清单定义：**框架问题与缺陷**（架构 / 安全 / 可靠性 / 一致性 / 工程化），需要优先修改而未完成的内容；不收录普通业务功能（见 `docs/改造清单-二级应用.md`）。
> 推进约定：本清单优先级高于二级清单；每完成一项同步 `docs/改造记录.md`。

## 1. 框架缺陷与待办（主线）

| 编号 | 项目 | 类别 | 涉及模块 | 现状与依据 | 目标 / 验收 | 优先级 | 状态 |
|------|------|------|----------|------------|-------------|:---:|:---:|
| A1 | 登录防爆破：失败锁定 + 限流 | 安全缺陷 | iam-authorization-server | `sys_user.account_non_locked / account_non_expired` 字段已具备但**无任何逻辑**；无失败计数（原 R4，设计说明书 §21 残留问题） | 连续失败 N 次锁定 / 指数退避；管理端解锁（复用现有启用/禁用接口扩展） | 高 | ⬜ |
| A2 | 内部 / 开放接口限流与调用审计（防滥用） | 安全缺陷 | iam-resource-service | `/api/internal/**`、`/api/capability/**` 仅靠鉴权，限流“仅登记断言无计数表”；枚举 / 重放无拦截（原 R7） | 调用计数归 `iam_capability_usage` 另表 + 限流（QPS 断言）+ 关键调用留痕 | 高 | ⬜ |
| A3 | 管理面变更审计（操作日志） | 安全加固 | auth + resource + admin | 用户 / 客户端 / 会话 / 策略 / 能力等管理变更**无审计留痕**（原 R2 缓解项：管理 API 需“鉴权 + 审计”）；`iam_admin` 操作日志未建 | 敏感管理操作写审计日志（谁 / 何时 / 改了什么 / 前后值），管理台可查 | 高 | ⬜ |
| A4 | OAuth2 授权与 SSO 会话持久化 | 可靠性（已决暂缓） | auth + IAM | 授权状态 / SSO 会话仅 Redis，撤销即删，**重启即丢**（原 R3，本轮明确“先不动”） | 触发条件成熟时引入 JDBC 授权服务 + Spring Session JDBC（DB 真源、Redis 缓存，**不做双写**） | 低（触发型） | ⬜ 暂缓 |
| A5 | 凭据 / 密钥治理与生产加固 | 安全缺陷 | 各服务 | yaml / Java 中硬编码演示凭据（`123456`：客户端密钥、service-token、种子密码 BCrypt）；无 HTTPS / MFA / 容器化（原 R8）<br />`其他硬编码` | 敏感配置走环境变量 / 密钥托管，演示密码仅限 dev profile；HTTPS、MFA、容器化按规范补齐 | 高 | ⬜ |
| A6 | 迁移 / 初始化收口 SQL（去 Java 初始化类） | 工程化缺陷 | 两中心 | 启动时仍有 **7 个 ApplicationRunner** 执行 DDL / 种子 / 破坏性迁移（`ShadowUserMigrationInitializer`、`CrossDbCodeMigrationInitializer`、`EndpointPolicyScanInitializer`、`CapabilitySchemaInitializer`、`DataInitializer`、`TenantUserMigrationInitializer`、`UserPasswordInitializer`），与《备忘》“初始化脚本不要再用 init 类文件”约定冲突，幂等 / 可审计性差 | DDL / 迁移 / 种子统一落到 `resources/migration/V{版本}__*.sql`；Java 初始化类拆除或幂等化并留注释（`rescan()` 类运行期刷新除外） | 中 | ⬜ |

## 2. 已完成（原清单逐项核对归档）

| 原项（改造清单 V0.3） | 现状（2026-08） | 结论 |
|----------------------|-----------------|:---:|
| D1–D8 前置决策 | 全部落地：用户收回全量 IdP、资源中心 5 表、统一 SSO、端口、内部鉴权 client_credentials+introspection、演示重跑种子、门户应用列表正式化（见下） | ✅ |
| D9 用户双写一致性 | 改以 **V6.2 去影子用户 + user_code 统一寻址 + 内省判定修正（grant_type+client_id 白名单，不再由“本地查不到用户”反推服务令牌）+ 删除用户联动清理**（认证中心 DELETE → 资源中心 `/api/internal/user/{userCode}/data`）解决，**不再双写** | ✅ |
| Phase 1 库拆分 | `iam_identity.sql`（OAuth2 表 + sys_user + 租户 + 客户端策略 + 外部身份绑定）与 `iam_authorization.sql`（RBAC 5 表 + 应用/渠道/组织/授权/端点策略/能力）就绪，种子齐备 | ✅ |
| Phase 2 资源中心 RBAC | 5 表 Mapper/Service、`/api/admin/roles\|permissions` 管理接口可 CRUD；**内部角色供给已接线**（`PortalUserDetailsService`→`RemoteRoleService.getUserRoles(userCode)`，角色权威在资源中心，原“改造清单 #17”状态已闭合） | ✅ |
| Phase 3 认证中心全量 IdP | 本地凭据认证（零远程凭据调用）；三域管理 API（users/clients/sessions|records）；会话/强制下线按 user_code 联动 | ✅ |
| Phase 4 portal 收紧 | `PORTAL_SERVICE_TOKEN + authserver.portal-client-ids` 双闸门；`/api/public/clients/mine` 唯一入口；死代码与失效策略行已清 | ✅ |
| Phase 5 管理域 | admin-service（统一 SSO、ADMIN_SERVICE_TOKEN 管理凭证）；admin-web 全部页面（含用户/应用/策略/能力/在线/授权） | ✅ |
| D8 应用目录二期（表/服务/页面） | **实际已完成**：`iam_application / iam_application_channel / iam_app_authorization` 三表 + `ApplicationService` + 管理端三级 API + 门户 `mine` 按 `visible + 授权` 过滤；渠道密钥方案 A（密文存认证中心，`secret_status` 仅展示标识） | ✅ |
| V6.x 迁移与语义 | 准入配置表化（iam_client_policy / iam_endpoint_policy 扫描播种 + 管理覆盖）；令牌类别更名（ADMIN_SERVICE_TOKEN / PORTAL_SERVICE_TOKEN）；准入要求最新语义（portal 收紧 / permitall 放行域） | ✅ |
| V6.7 外部身份绑定表 | `iam_external_identity` 已建（迁移 + 基线 + 本地库验证），仅建表 | ✅ |
| admin-web 易用性（2026-08-16） | 用户编码缩略展示（复用 `App.maskUser`）+ 复制按钮（复用 COPY_ICON） | ✅ |
