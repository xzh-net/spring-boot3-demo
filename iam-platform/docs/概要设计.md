# 概要设计

统一认证管理平台的高层设计——**要做什么、为什么这么做**。实现细节见 [详细设计](./详细设计.md)。

---

## 一、系统定位

| 维度 | 现状 |
|---|---|
| 能力 | OAuth2 2.0 / OIDC 1.0 全流程（授权码、密码、设备码、刷新）+ 平台内权限治理 |
| 形态 | **单服务单库**：原认证中心与原资源中心合并为一个 Spring Boot 进程 |
| 服务 | `:9000` 唯一服务端（协议 + 管理 API + 业务 API + 准入裁决） |
| 数据 | 单 MySQL 库 `iam`（16 表，零租户）+ Redis（会话 / 令牌运行时态） |
| 权限 | **双维**：用户 RBAC 码 ∩ 客户端 scope 码，fail-closed |
| 面向 | 内部统一认证（管理后台 / 门户 SSO）+ 三方应用标准接入 |

```text
                    浏览器 / 三方应用
                          │
     ┌────────────────────┼─────────────────────┐
     ▼                    ▼                     ▼
:8001 管理前端        :8000 门户前端        三方后端/SPA
 (静态 HTML)           (静态 HTML)         (直连协议端点)
     │                    │                     │
     ▼                    ▼                     │
:8085 管理 BFF        :8080 门户 BFF            │
 (OAuth2 Client        (OAuth2 Client           │
  admin-app)            portal-app+PKCE)        │
     └────────────────────┼─────────────────────┘
                          ▼
                    :9000 服务端  ◄──── 唯一业务入口
                 (协议端点 + 管理/业务 API)
                     │          │
                     ▼          ▼
              MySQL `iam`    Redis db1
              (16 表持久)   (会话/令牌，非持久)
```

**端口分段**：`8000~8009` 前端静态站 ｜ `8080~8089` BFF 与演示 ｜ `9000` 服务端核心。

## 三、模块划分

| 模块 | 端口 | 层 | 职责 | 有无库 |
|---|---|---|---|---|
| `server/iam-authorization-server` | 9000 | 服务端 | 协议运行时 + 三域管理 API + 业务 API + RBAC + 端点准入 + 签发准入 | `iam` + Redis |
| `bff/iam-admin-bff` | 8085 | 体验面 | OAuth2 Client(admin-app)，Bearer 透传管理 API | 无 |
| `bff/iam-portal-bff` | 8080 | 体验面 | OAuth2 Client(portal-app, PKCE)，门户业务 | 无 |
| `web/iam-admin-web` | 8001 | 前端 | 管理后台静态站（含只读字典页） | 无 |
| `web/iam-portal-web` | 8000 | 前端 | 门户静态站 | 无 |
| `client/iam-client-*-demo` | 8081~8083 | 示例 | 授权码+密码 / 设备码 / PKCE 三种接入姿势 | 无 |

## 四、技术选型

| 项 | 选择 | 一句话理由 |
|---|---|---|
| 框架 | Spring Boot 3.4 + Spring Security 6.2 | 与 SAS 1.4.1 官方适配 |
| 授权服务器 | Spring Authorization Server 1.4.1 | 官方 OAuth2/OIDC 实现 |
| ORM | MyBatis-Plus（单表 + 分页插件） | 表结构简单，避免过度抽象 |
| 缓存 | Redis（会话、令牌、客户端配置缓存） | 撤销即删 key，运行时态与业务持久分离 |
| 前端 | 纯静态 HTML + 原生 JS | 无构建链，BFF 代理鉴权 |
| 迁移 | 无框架，SQL 脚本手动执行 | 避免启动期 DDL |

## 五、核心架构决策

| # | 决策 | 选择 | 与备选的关系 |
|---|---|---|---|
| 1 | 单服务 vs 微服务 | **单服务** | 角色/准入全进程内完成，消除跨服务延迟与 M2M 凭证治理；服务数=1，不足以支撑注册中心 |
| 2 | Access Token 格式 | **Opaque（REFERENCE）强制** | 业务方不解析令牌、撤销即删 Redis key；切 JWT 会破坏本地内省模型 |
| 3 | 令牌校验 | **同进程内省**（查 Redis，无 HTTP 自回环） | `/oauth2/introspect` 保留给外部资源服务器 |
| 4 | 权限模型 | **双维交集**（用户 RBAC ∩ 客户端 scope） | 单一词表 `sys_permission`，避免"第二权威"；scope 封顶用户角色可行使范围 |
| 5 | 未授权默认 | **fail-closed** | 签发/自省/端点三层任一缺口即拒绝，无猜测放行 |
| 6 | 字典与准入数据演进 | **SQL 种子**（`sys_scope` 族、端点准入） | 避免"页面"与"种子"双演进路径打架 |
| 7 | 端点准入同步 | **启动自扫描补缺** | 端点目录随代码自动增补；精确权限码权威仍在种子 |
| 8 | 迁移 | **不接** Flyway/Liquibase | 存量升级由 DBA 手动执行 `sql/migration/` |
| 9 | 注册中心 | **不引入** | 固定端口 + 配置直连；引入判据：>10 服务且频繁上下线 / 需多实例发现 |

## 六、核心数据流

```text
                     sql/iam.sql（种子权威）
                             │
        ┌────────────────────┼──────────────────────┐
        ▼                    ▼                      ▼
   sys_user ──┐        sys_permission ◄────── sys_scope
              │              ▲                └─ sys_scope_permission
        sys_user_role → sys_role                 │
              └→ sys_role_permission ────────────┤
                                                 │
        oauth2_registered_client.scopes ─────────┘   (客户端持有 scope 码)

  令牌 authorities = 业务角色码 + (用户码 ∩ scope 展开码)     ← ②自省层
        │
        ▼
  iam_endpoint_policy.required_authority ∈ authorities ?  → 放行 / 403   ← ③端点准入
        （签发前另有 ①签发准入：交集为空则拒发码）
```

## 七、与业界标准的对照

| 本设计 | 对应标准/模式 | 说明 |
|---|---|---|
| 客户端 scope 展开能力 | RFC 6749 资源收窄语义 | 粗 scope 展开为细粒度码是常见服务端做法 |
| 双维交集 | capability（客户端）× RBAC（用户）混合模型 | scope 封顶角色可行使范围 |
| 签发前判"用户能否用该客户端" | OAuth2 受众约束（audience restriction） | 在 `/oauth2/authorize` 拒发码 |
| 表驱动端点准入 | XACML PDP「策略即数据」 | 代价是无参照完整性 → 码不可改名 |
| Opaque 令牌 + 内省 | RFC 7662 | 外部资源方走 `/oauth2/introspect` |
| RP-Initiated Logout | OIDC 标准 | `/oidc/logout` |

| 项 | 状态 | 接替者 |

| 租户体系（`iam_tenant` 等） | 整体移除 | — |
| M2M / `client_credentials` 分支 | 已退役 | 按需以 `m2m.*` scope 重建 |
