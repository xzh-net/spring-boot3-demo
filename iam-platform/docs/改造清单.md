# IAM 平台改造清单（认证中心全量 IdP + 管理统一 SSO + 资源中心业务 RBAC）

> 文档版本：V0.3（决策定版 | IdP 自持用户源）
> 更新日期：2026-08-13
> 定版依据：设计说明书 V5.0 + D1–D9 决策（原 `docs/架构.md` 内容已并入设计说明书并归档删除，其 `iam_identity` 仅 3 表的旧表述与 V5 用户收回定版冲突，故弃用）
>
> 本轮定版三件事：
> 1. **用户收回认证中心（全量 IdP）**：凭据/账号状态归 `iam_identity`，认证中心本地校验，登录零远程凭据调用（哈希/明文零跨服务）。
> 2. **管理后台统一 SSO**：admin-service 作为 OAuth2 Client 接入认证中心 `/login`，管理端所有管理操作经用户 token + `hasRole('ADMIN')` 把关。
> 3. **资源中心按 5 张 `sys_*` 表开发**（库表归属见设计说明书 §12.1.1）；门户应用列表暂用 `oauth2_registered_client` 测试对接，应用目录表待二期。
>
> 本轮追加决定：**授权码/OAuth2 运行时与在线会话的持久化先不动**（维持 Redis-only + 撤销即删，见 R3），不新增 `oauth2_authorization` / 在线会话表。

## 满足/不满足业界标准的更新评估

### 已解决（相对 V0.1）
- ✅ 哈希跨服务传输 → **零外传**（用户收回，本地认证）
- ✅ 管理后台“不参与 SSO”的矛盾 → **统一 SSO 定版**
- ✅ 认证中心用户职责归属不清 → 用户/客户端/会话三域管理 API 明确

### 残留问题（登记为已知取舍/二期）
| # | 问题 | 说明 | 缓解/计划 |
|---|------|------|-----------|
| R1 | `sys_user` 双库一致性 | 凭据主库在 identity，业务视图在 authz | D9：认证中心权威写入 + 同步，清单含实现任务 |
| R2 | 认证中心敏感数据集中 | 账号+凭据+客户端+会话集中一处，管理 API 面最大 | 管理 API 必须 ADMIN 鉴权 + 审计 + 未来 MFA |
| R3 | OAuth2 授权状态仅 Redis，无 `oauth2_authorization` 表（含在线会话无 DB 持久化） | 重启丢授权记录/SSO 会话；**本轮决定先不动**，维持 Redis-only + 撤销即删 | 取舍登记于设计说明书 §21.7；需持久审计时引入 JDBC 授权服务/Spring Session JDBC（DB 为主、Redis 缓存，不做双写） |
| R4 | 无失败登录锁定/限流 | `account_non_locked` 字段存在但无逻辑 | 二期补策略 |
| R5 | 无密码策略生命周期、审计日志（iam_admin.操作日志）、组织模型 | 企业 IAM 常见能力 | 远期 |
| R6 | 门户应用列表 = 客户端表 | 应用目录与客户端注册混用（临时） | D8：二期建 `iam_application` 目录 |
| R7 | 内部角色接口仍需防滥用 | 虽不含凭据，仍可枚举/重放 | D6：内部鉴权 + 内网隔离 + 限流 + 日志 |
| R8 | 生产加固项 | HTTPS、MFA、密钥托管、容器化 | 演示环境 localhost 明文仅限 dev |

## 风险登记

| 风险 | 说明 | 缓解 |
|------|------|------|
| 登录取角色依赖资源中心 | 凭据本地校验成功，角色获取失败 | 降级默认 ROLE_USER + 告警；不等同于认证失败 |
| 用户双库漂移 | D9 未实现前禁用/改密与业务视图不一致 | 首启先做同步任务，再切换流量 |
| Redis 重启丢授权状态/会话 | 无 OAuth2 持久化表 / 在线会话表；本轮**先不动** | 已知取舍；需恢复力时走 JDBC 授权服务 + Spring Session JDBC（DB 真源、Redis 缓存，不做双写） |
| 门户列表跨库依赖 | 资源中心 → 认证中心客户端目录 | D6 鉴权 + 失败兜底返回空列表 |
| 手工数据迁移丢失 | 重跑种子仅覆盖内置数据 | D7 决策 |
