## 2026-08-15（改造清单 V0.4 缺陷推进：用户标识统一 + 准入配置表化 + 去影子用户）

### 一、缺陷4/改名（Phase 1）— 用户标识统一 user_code/user_label + 租户

- `SysUser` 新增 `user_code`（业务用户编码，u_ + 32 位随机 hex，对外/下放引用，内部主键不下放）与 `user_label`（业务标签，替换废弃的 identity_type：1/2/3 → admin/client/wechat）。
- 新增租户表 `sys_tenant` / `sys_user_tenant` + `TenantService`；管理 API `users.tenantIds` 返回归属租户；`iam_identity.sql` 基线同步更新。
- 验证：租户列表（T001/演示企业）、用户列表 userCode/userLabel/tenantIds 均正确。

### 二、缺陷1 系统准入配置 yaml → 表 + 全部走 RBAC（Phase 2）

- 新增 `iam_client_policy` 表（`ClientPolicy` / `ClientPolicyMapper`）+ `ClientPolicyTableInitializer`（启动幂等建表 + 补种 admin-app→ADMIN）；管理端 `AdminClientPolicyApiController`（/api/admin/policies）+ `policy.html`。
- 删除 `authserver.client-identity-policy` yaml 与 `AuthServerProperties.clientIdentityPolicy`；`ClientUserPolicyService` 重写为表驱动：无策略行/空或`*`放行，否则用户 RBAC 角色与 allowed_roles 交集非空才签发，角色解析失败 fail-closed。
- 新增 `RemoteRoleService`：resource-server client_credentials 服务令牌调用资源中心 D6 `/api/internal/user/{userCode}/roles`，进程内 TTL 缓存 30s。
- 角色权威正式迁移到资源中心 RBAC：登录 principal authorities / 发码准入 / 签发准入 / 刷新准入（授权码、密码、设备码、refresh）全部按 D6 角色判定。
- 线上数据修正：资源中心 `user` 角色由误配 [1]（ADMIN）修正为 [2]（USER）。

### 三、缺陷2 删除影子用户表 + sub=user_code（Phase 3）

- 资源中心删除影子 `sys_user`（`SysUser.java` / `SysUserMapper.java` 删除）；`sys_user_role.user_id` → `user_code`（varchar(64)，唯一索引 uk_user_code_role）；`SysRoleMapper` / `SysPermissionMapper` / `PermissionService` / `RbacService` 全量改按 user_code 解析。
- `RbacAuthoritiesOpaqueTokenIntrospector`：sub=user_code 直接解析 RBAC；`ContactsController` 不再依赖影子表。
- 内部接口改 `GET /api/internal/user/{userCode}/roles`（响应 `{userCode, roles:[ROLE_*], permissions}`，hasRole('SERVICE') 把关）；管理接口改 `/api/admin/user-roles/{userCode}`。
- 认证中心：`PortalUserDetailsService` principal name=user_code，authorities 由 D6 RBAC 供给（资源中心不可达降级 user_label 映射，避免管理端锁死）；新增 `loadUserByUserCode`（设备码链路反查）；id_token `preferred_username` 按 user_code 反查真实用户名；`RedisOpaqueTokenIntrospector` 按 user_code 反查 authorities（兼容历史令牌按用户名）。
- `AuthSessionService` / `UserService`（踢线/重置密码）改按 user_code 关联会话；admin-web 角色分配改 userCode。
- 迁移：`ShadowUserMigrationInitializer`（资源中心启动幂等：跨库从 iam_identity.sys_user 回填 user_code → 删孤儿行 → 删影子表）；SQL：`migration/V6.1__iam_client_policy.sql`、`V6.2__drop_shadow_user.sql`。

### 四、验证结果（Phase 1/2/3 全绿）

| 场景 | 结果 |
|------|------|
| 租户/用户列表（userCode/userLabel/tenantIds） | 通过 |
| 准入策略 admin-app=ADMIN（表配置） | 通过 |
| 管理端 admin 登录 admin-app / 管理 API | 通过（502 → 8085 回调 → 8001 → 200） |
| C 端 user（ROLE_USER）申请 admin-app | 发码阶段拒绝 → login.html?error |
| 令牌 introspect / id_token | sub=user_code，preferred_username=admin，roles=ROLE_ADMIN |
| D6 按 user_code | admin→ROLE_ADMIN+4 权限，user→ROLE_USER+2 权限 |
| 影子表 sys_user | 已删除（迁移日志：回填 2 行，孤儿 0 行） |
| 角色分配按 user_code | admin→[1]，user→[2] |

> 注意：xuchaoguo（userLabel=admin）在 RBAC 中暂无角色 → D6 返回空 → 无法通过 admin-app 准入（RBAC 权威生效）。如需恢复其管理能力，用管理端「分配角色」为其绑定 ADMIN 角色。

## 2026-08-15（认证中心全量 IdP + 管理统一 SSO + 资源中心业务 RBAC + 令牌准入策略）

### 一、认证中心 → 全量 IdP（用户收回本地认证）

- **用户权威库收回 `iam_identity`**：`sys_user`（用户名/密码哈希/账号状态）在认证中心本地，登录零远程凭据调用；新增 `iam_identity.sql`（OAuth2 3 表 + `sys_user`），删除 `oauth2_server.sql` / `schema.sql`。
- `sys_user` 新增 `identity_type` 字段（`1=管理端, 2=客户端, 3=微信端`），作为令牌签发准入的判定依据。
- 删除 `AdminUserDetailsService`、admin Thymeleaf 页面、`controller/admin/*` 表单控制器、Order(3) `/admin/**` 表单链 → 管理入口统一走 Order(1) 登录。
- `PortalUserDetailsService` 改本地库查询；`LoginController` 登录失败统一跳 `/login.html?error`。
- 新增管理 REST API **三域**（`controller/api/`，Bearer + introspection + `ROLE_ADMIN` + 客户端白名单）：
  - `AdminUserApiController`（账号/凭据/启用锁定）
  - `AdminClientApiController`（客户端/密钥）
  - `AdminSessionApiController` / `AdminRecordApiController`（在线会话/踢线/授权记录）
- 新增 `AuthServerProperties`：`authserver.admin-client-ids`（管理 API 客户端白名单）。
- `OAuth2RegisteredClientMapper` / `JdbcRegisteredClientRepository` 切换 iam_identity 库表；`RedisOAuth2AuthorizationService` / `RedisOpaqueTokenIntrospector` / `EnrichedOAuth2TokenIntrospectionAuthenticationProvider` 配合会话与授权记录管理改造。

### 二、资源中心 → 业务 RBAC（5 张 sys_* 表）

- 新增 `iam_authorization.sql`（业务 RBAC 5 表：`sys_role` / `sys_permission` / `sys_user_role` / `sys_role_permission` + `sys_user` 业务视图），含角色/权限/关联种子。
- 新增 Entity/Mapper/Service：`SysPermission` / `SysRole` / `SysRolePermission` / `SysUserRole`、对应 4 个 Mapper、`RbacService`。
- 新增控制器分组：`controller/admin`（角色/权限 CRUD）、`controller/client`、`controller/internal`（内部角色供给接口，仅回角色/权限不含凭据）、`controller/portal`。
- 新增 `RbacAuthoritiesOpaqueTokenIntrospector`：内省时按本地 RBAC 组装 `ROLE_*`；`ResourceServerConfig` 对应调整；删除 `ContactsController` / `PublicClientController` / 资源中心直读客户端表逻辑。

### 三、管理后台新增 admin-service（8085）/ admin-web（8001）

- 新增 `iam-admin-service`（无库，纯 BFF）：OAuth2 Client（授权码模式）统一 SSO 接入认证中心；`AdminOnlyLoginSuccessHandler` 管理端准入；透传 `/api/**` 与用户 token 到认证中心三域 API + 资源中心角色/权限 API。
- 新增 `iam-admin-web`（8001，纯 HTML 零依赖 Node 静态服务）：登录、用户、客户端、角色、权限、在线会话、授权记录、健康页；`/login` `/logout` 302 到 admin-service。

### 四、令牌签发准入策略（客户端 × 身份类型）【本次会话重点】

- 新增 `ClientUserPolicyService`：按 `client_id` 配置允许的 `identity_type` 集合，比对用户真实身份类型，不合规抛 `access_denied`，不签发任何令牌；未配置策略的客户端默认放行。
- 新增策略感知提供者 `PolicyAwareAuthorizationCodeAuthenticationProvider` / `PolicyAwareRefreshTokenAuthenticationProvider`：包装 SAS 默认提供者，签发前先过策略。
- `PasswordGrantAuthenticationProvider` / `DeviceCodeGrantAuthenticationProvider` 注入同一策略校验。
- 新增 `AuthorizePolicyFilter`：授权端点 `/oauth2/authorize` **发码阶段**同样拦截，已登录用户身份类型不合规时直接 302 回 `9000/login.html?error`（与密码错误体验一致），**不签发授权码**；注册在 `SecurityContextHolderFilter` 之后。
- 配置：`authserver.client-identity-policy`（`admin-app: [1]` 等），后续微信 H5 加 `wechat-app: [3]` 即可，零代码改动。

### 五、退出流程修复

- `AuthLogoutController` 重定向目标由 `{issuer}/connect/logout`（SAS 默认 OIDC 端点已被自定义覆盖 → 404）改为认证中心自定义 `{issuer}/logout?post_logout_redirect_uri=...`。
- admin-service `SecurityConfig` 禁用默认 `LogoutFilter`（否则 GET `/logout` 被拦截跳到 `/login?logout` 404，`AuthLogoutController` 无法执行），并放行 `/logout`。

### 六、验证结果

| 场景 | 结果 |
|------|------|
| 管理端 `admin` 登录 admin-app | 通过，换 token 成功，管理 API 200 |
| C 端 `user`（identity_type=2）申请 admin-app | 发码阶段即被拒 → `9000/login.html?error`，无 code、无 token、clientSession=0 |
| 密码错误（回归） | 302 `/login.html?error`，与 C 端被拒体验一致 |
| 在线用户列表 | `admin` client>0 正常；`user` clientSession=0（全程无令牌） |
| 退出链路 | 8001→8085→9000 `/logout` →8001 `/logged-out` 200 |
