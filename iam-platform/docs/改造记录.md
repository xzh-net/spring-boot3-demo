## 2026-08-16（准入要求最新语义：portal 收紧 + 放行域新增 + 令牌类别更名）

### 一、portal 端收紧为「门户服务凭证 + 门户客户端白名单」（原错误：PERMIT_ALL 任意放行）

- `EndpointPolicyService.defaultAuthorityOf`：`portal` 默认准入要求由 `PERMIT_ALL` → `PORTAL_SERVICE_TOKEN`（门户服务凭证）；`EndpointAdmissionManager` 把 internal 专用 `isServiceOnly` 抽为统一 client 白名单闸门，新增 portal 闸门（`client_id ∈ authserver.portal-client-ids`，默认 `[portal-app]`），对任意准入要求（含 override）生效——门户信息不再对任意客户端开放。
- `RbacAuthoritiesOpaqueTokenIntrospector`：`client_id ∈ portal-client-ids`（门户应用客户端，如 portal-app）签发的**用户令牌**在注入业务 RBAC 之外**追加 `PORTAL_SERVICE_TOKEN`**，作为 portal 域门票；服务令牌判定与 internal 白名单不变——portal-app 令牌持证但不在 `service-client-ids`，仍进不了 internal。
- 新增配置 `authserver.portal-client-ids`（yaml，`AuthServerProperties.portalClientIds` 兜底 `Set.of("portal-app")`）。
- `rescan()`：coded 行自动对齐代码默认（override 不动），并**清理失效 coded 行**（端点已从代码删除时旧播种行一并移除，如废弃的 `GET /api/public/clients`），存量行重启即升级，无需手工 SQL。

### 二、新增放行域 permitall（`controller/permitall`）

- 新增包 + `TimeController`（`GET /api/permitall/time` 返回服务端时间），`EndpointPolicyService.resolveDomain` / `defaultAuthorityOf` 增加 `permitall → PERMIT_ALL`；放行域从此只承载有意识的公开测试端点，与 portal 严格区分。
- `PublicClientController` 清理：删除无调用方的 `GET /api/public/clients`（透传认证中心目录，陈旧）+ 私有目录获取链（`directory/fetchServiceToken/fetchDirectory/CachedDirectory`），仅保留 `GET /api/public/clients/mine`（当前人员应用列表，portal-service 唯一入口）。

### 三、令牌类别更名（全链路一致）

- `MANAGEMENT_TOKEN`（管理令牌）→ `ADMIN_SERVICE_TOKEN`（管理服务凭证）：认证中心签发（`PortalUserDetailsService`）、Order(2) 管理链裁决（`AuthorizationServerConfig`）、会话管理（`AuthSessionService`）、资源中心内省注入与端点策略、管理前端守卫 `common.js` / `endpoint_policy.html` 全部同步。
- `SERVICE_TOKEN`（服务令牌）→ `PORTAL_SERVICE_TOKEN`（门户服务凭证）：资源中心内省注入、internal/portal 域端点策略、文档同步。
- `AUTHENTICATED` 表述统一「任意已认证 → 任意凭证」。
- SQL：`migration/V6.6__endpoint_policy_token_rename.sql`（portal→PORTAL_SERVICE_TOKEN + 两类更名，幂等；新库由扫描初始化器直接播种新值）。
- 术语清理：`ROLE_ADMIN` / `ROLE_SERVICE` 旧称在文档/注释中替换为新的令牌类别名。

- 新增 `iam-admin-service`（无库，纯 BFF）：OAuth2 Client（授权码模式）统一 SSO 接入认证中心；`AdminOnlyLoginSuccessHandler` 管理端准入；透传 `/api/**` 与用户 token 到认证中心三域 API + 资源中心角色/权限 API。

### 四、令牌签发准入策略（客户端 × 身份类型）【本次会话重点】

- 新增 `ClientUserPolicyService`：按 `client_id` 配置允许的 `identity_type` 集合，比对用户真实身份类型，不合规抛 `access_denied`，不签发任何令牌；未配置策略的客户端默认放行。
- 新增策略感知提供者 `PolicyAwareAuthorizationCodeAuthenticationProvider` / `PolicyAwareRefreshTokenAuthenticationProvider`：包装 SAS 默认提供者，签发前先过策略。
- `PasswordGrantAuthenticationProvider` / `DeviceCodeGrantAuthenticationProvider` 注入同一策略校验。
- 新增 `AuthorizePolicyFilter`：授权端点 `/oauth2/authorize` **发码阶段**同样拦截，已登录用户身份类型不合规时直接 302 回 `9000/login.html?error`（与密码错误体验一致），**不签发授权码**；注册在 `SecurityContextHolderFilter` 之后。
- 配置：`authserver.client-identity-policy`（`admin-app: [1]` 等），后续微信 H5 加 `wechat-app: [3]` 即可，零代码改动。

### 五、退出流程修复

- `AuthLogoutController` 重定向目标由 `{issuer}/connect/logout`（SAS 默认 OIDC 端点已被自定义覆盖 → 404）改为认证中心自定义 `{issuer}/logout?post_logout_redirect_uri=...`。
- admin-service `SecurityConfig` 禁用默认 `LogoutFilter`（否则 GET `/logout` 被拦截跳到 `/login?logout` 404，`AuthLogoutController` 无法执行），并放行 `/logout`。
