# 接口文档

对外暴露的全部接口，以及三方系统的接入方式。基准地址 `http://localhost:9000`（管理后台经 BFF `:8085` 代理）。

---

## 一、接口总览

| 分组 | 路径前缀 | 鉴权 | 说明 |
|---|---|---|---|
| 协议端点 | `/oauth2/**`、`/.well-known/**` | 客户端认证 / 用户登录 | OAuth2 / OIDC 标准端点，三方接入主入口 |
| 用户信息 | `/userinfo` | Bearer（access_token） | OIDC UserInfo，本地内省自鉴权 |
| 管理端业务 | `/admin/**` | **Bearer + 权限码** | 48 个准入点，按 `iam_endpoint_policy` 裁决 |
| 门户业务 | `/biz/**` | **Bearer + 权限码** | 门户应用中心卡片 |
| 免令牌 | `/permitall/**` | 无 | 链层放行（如健康/时间探测） |
| 表单页 | `/login*`、`/consent`、`/logout` | 会话 | 登录/同意/登出 |

**鉴权结论**：业务接口 = 有效 Opaque 令牌 **且** 令牌 authorities 含该端点所需的权限码
（`required_authority`），两条件缺一 403。详见 [权限与安全设计](./权限与安全设计.md)。

---

## 二、协议端点（三方接入主入口）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/.well-known/openid-configuration` | OIDC 发现文档（issuer = `http://localhost:9000`） |
| GET | `/.well-known/oauth-authorization-server` | RFC 8414 授权服务器元数据 |
| GET | `/.well-known/jwks.json` | 签名公钥（验 ID Token） |
| GET | `/oauth2/authorize` | 授权端点（发授权码） |
| POST | `/oauth2/token` | 令牌端点（换 code / 密码 / 刷新 / 客户端凭证） |
| POST | `/oauth2/introspect` | 令牌内省（RFC 7662，外部资源服务器用） |
| POST | `/oauth2/revoke` | 令牌撤销（RFC 7009） |
| POST | `/oauth2/device_authorization` | 设备码授权请求（RFC 8628） |
| GET/POST | `/oauth2/device/verify` | 设备码用户验证页 |
| GET | `/userinfo` | OIDC UserInfo（Bearer） |
| POST | `/oidc/logout` | RP-Initiated Logout |
| — | `/login` `/consent` `/logout` | 表单登录 / 同意 / 登出 |

> Access Token 为 **Opaque（REFERENCE）**，资源方不可自行解析，必须走内省或本服务直连。

## 三、管理端业务接口（`/admin/**`）

按资源域分组，`(*)` = 需写权限码：

### 用户 `user:read` / `user:write`
```text
GET    /admin/users                          用户列表
GET    /admin/users/{id}                     用户详情
POST   /admin/users *                        创建
PUT    /admin/users/{id} *                   修改
DELETE /admin/users/{id} *                   删除
PUT    /admin/users/{id}/enable *            启用/停用
POST   /admin/users/{id}/reset-password *    重置密码
GET    /admin/users/{id}/sessions            用户会话
DELETE /admin/users/{id}/sessions *          踢会话
DELETE /admin/users/{userCode}/data *        清数据
```

### 角色 `role:read` / `role:write`
```text
GET|POST          /admin/roles               角色列表 / 创建
PUT|DELETE        /admin/roles/{id} *        修改 / 删除
GET|PUT           /admin/user-roles/{userCode}  查/改用户角色绑定
```

### 权限码 `permission:read` / `permission:write`
```text
GET   /admin/permissions                     权限码列表
POST  /admin/permissions *                   创建
PUT   /admin/permissions/{id} *              修改
DELETE /admin/permissions/{id} *             删除（被端点引用中的码不可删）
```

### 授权范围 `client:read`（只读）
```text
GET   /admin/scopes                          scope 字典（含内含码与引用客户端）
```
> 字典只读：`sys_scope` / `sys_scope_permission` 的增删改走 `sql/iam.sql` 种子。

### 客户端 `client:read` / `client:write`
```text
GET   /admin/clients                         列表
GET   /admin/clients/{id}                    详情
POST  /admin/clients *                       创建
PUT   /admin/clients/{id} *                  修改（含 scopes 勾选）
DELETE /admin/clients/{id} *                 删除
POST  /admin/clients/{id}/reset-secret *     重置密钥（一次性返回明文）
```
> **校验规则**（服务端权威，前端已联动）：
> - `authorizationGrantTypes` 含 `authorization_code` → **必须 `requireProofKey=true`**，否则 `code:400`「授权码模式必须开启 PKCE」
> - 含 `authorization_code` → 必须配至少一个 `redirectUris`
> - 认证方式含 `none`（Public）→ 不得设置 `client_secret`
> - `clientSecret` 传明文会被 BCrypt 编码；**传入已是哈希的值会原样保留**（防"读-改-写"把哈希二次编码）

### 端点准入 `policy:read`（只读）
```text
GET   /admin/endpoint-policies               准入点列表
```
> 唯一写入方 = 启动自扫描补缺；精确权限码权威 = 种子。页面无增删改。

### 会话 `session:read` / `session:write`
```text
GET    /admin/sessions/online                 在线用户
GET    /admin/sessions/users/{id}             某用户全部会话
POST   /admin/sessions/users/{id}/logout *    按用户强制下线
POST   /admin/sessions/{ssoSessionId}/logout *按 SSO 会话下线
DELETE /admin/sessions/online/{username} *    撤销该用户全部令牌
```

### 应用与授权 `application:read` / `application:write`
```text
GET|POST|PUT|DELETE /admin/applications[/{id}]           应用 CRUD
GET|POST           /admin/applications/{appId}/channels   渠道查询/新增
PUT|DELETE         /admin/applications/{appId}/channels/{channelId}  渠道改/删
GET                /admin/applications/{appId}/authorizations  应用授权查询
POST|DELETE        /admin/applications/authorizations[/{id}]    授权绑定/解绑
```

### 授权记录 `record:read` / `record:write`
```text
GET    /admin/records                        授权记录
GET    /admin/records/consents               同意记录
DELETE /admin/records *                      清空记录
```

## 五、三方接入指南

### 5.0 前置

| 项 | 值 |
|---|---|
| Issuer | `http://localhost:9000` |
| 发现文档 | `GET /.well-known/openid-configuration` |
| 客户端注册 | 向管理方申请 `client_id` / `client_secret`（或走「客户端管理」页创建） |
| 默认测试客户端 | `admin-app` / `portal-app` / `web-app` / `device-app` / `mobile-app`，secret 均为 `123456` |
| 客户端认证 | `client_secret_basic`（除 `device-app`、`mobile-app` 为 `none`） |

**先拉元数据**（端点地址、支持的 grant/scope、JWKS 全部从这里取，不要硬编码）：

```bash
curl -s http://localhost:9000/.well-known/openid-configuration
```

### 5.1 授权码模式（Web / BFF / 传统服务端应用）

```text
① 浏览器 302 → /oauth2/authorize?response_type=code&client_id=...&redirect_uri=...
               &scope=openid profile read write&state=...[&code_challenge=...&code_challenge_method=S256]
② 用户在登录页认证（POST /login），服务端校验 client_id × scope → 合法则 302 回 redirect_uri?code=...
   ※ 若该用户角色与客户端授权范围交集为空 → 302 /login.html?error=access_denied（签发准入拒绝）
③ 后端换票：
   POST /oauth2/token
   Authorization: Basic base64(client_id:client_secret)
   Content-Type: application/x-www-form-urlencoded
   grant_type=authorization_code&code=...&redirect_uri=...[&code_verifier=...]
```

```bash
curl -s -u admin-app:123456 http://localhost:9000/oauth2/token \
  -d grant_type=authorization_code -d code=$CODE \
  -d redirect_uri=http://localhost:8085/login/oauth2/code/admin-app
```

**Public Client 必须带 PKCE；本平台现在所有授权码客户端都强制 PKCE**：
`admin-app`/`portal-app`/`web-app`/`mobile-app` 的 `requireProofKey` 均为 `true`，
授权请求**必须**携带 `code_challenge = BASE64URL(SHA256(code_verifier))` + `code_challenge_method=S256`，
换票时**必须**回传 `code_verifier`（缺任一个认证中心都会拒绝）。
`device-app` 走设备码、无授权码流程，不需要 PKCE。

### 5.2 密码模式（受信服务端场景，`web-app` 支持）

```bash
curl -s -u web-app:123456 http://localhost:9000/oauth2/token \
  -d grant_type=password -d username=admin -d password=123456 \
  -d scope=openid
```

### 5.3 设备码模式（输入受限设备，`device-app`）

```bash
# 1. 设备侧申请 device_code / user_code
curl -s -u device-app:123456 http://localhost:9000/oauth2/device_authorization \
  -d scope=openid -d device_id=demo-device
# 2. 用户在浏览器打开 /activate 输入 user_code 确认
# 3. 设备侧轮询换票
curl -s -u device-app:123456 http://localhost:9000/oauth2/token \
  -d grant_type=urn:ietf:params:oauth:grant-type:device_code -d device_code=$DEVICE_CODE
```

### 5.4 刷新令牌

```bash
curl -s -u admin-app:123456 http://localhost:9000/oauth2/token \
  -d grant_type=refresh_token -d refresh_token=$RT
```
> `reuseRefreshTokens=false`：**刷新即轮换**，旧 refresh_token 立即失效。

### 5.5 调用业务接口（拿票后）

```bash
curl -s -H "Authorization: Bearer $ACCESS_TOKEN" \
  http://localhost:9000/admin/users
```

**为什么可能 403**：令牌有效但 `required_authority` 要求的权限码不在令牌 authorities 里。
- 管理端接口需要令牌来自 `admin-app` 且用户角色绑了对应码（双维交集）
- 三方客户端只持有 `third.profile`（空映射）→ 拿不到任何业务码 → 业务接口全 403

### 5.6 令牌内省（外部资源服务器验票）

```bash
curl -s -u admin-app:123456 http://localhost:9000/oauth2/introspect \
  -d token=$ACCESS_TOKEN
# → {"active":true,"sub":"u_...","scope":"...","client_id":"admin-app",...}
```
`active=false` 即失效（撤销 = 删 Redis key）。

### 5.7 退出

- OIDC RP-Initiated Logout：`GET /oidc/logout?id_token_hint=...&post_logout_redirect_uri=...`
- 本地登出：`GET /logout`（partialLogout，按链路只清对应 SecurityContext）

## 六、响应结构

**业务接口**（`/admin/**`、`/biz/**`、`/permitall/**`）统一信封：

```json
{ "code": 200, "msg": "success", "data": [...], "timestamp": 1792927948555 }
{ "code": 403, "msg": "无权限", "data": null, "timestamp": ... }
```

**协议端点**（`/oauth2/**`）按 RFC 6749 错误格式：

```json
{ "error": "invalid_client" }
{ "error": "invalid_grant" }
{ "error": "access_denied", "error_description": "当前用户不允许在该客户端登录" }
```

## 七、接入自检清单

1. `GET /.well-known/openid-configuration` 能通，issuer 与实际地址一致
2. 客户端已在 `oauth2_registered_client` 注册，redirect_uri 与请求完全一致
3. 换票成功拿到 access_token（Opaque 字符串）
4. `POST /oauth2/introspect` 返回 `active=true`
5. 目标业务接口返回 200；若 403 → 查该端点 `required_authority` 与令牌权限码差集
6. 若签发阶段就被拒（`error=access_denied`）→ 用户角色与客户端 scope 无交集，找管理方调整 scope 或角色
