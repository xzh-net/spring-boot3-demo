# IAM 平台改造清单 · 二级（应用功能 · 不影响框架）

> 版本：V1.0（2026-08-16）。由原 `docs/改造清单.md`（V0.3）核对后拆分重组，原清单已删除。
> 二级清单定义：**不影响框架的应用功能**（业务能力新增 / 功能完善 / 工程化），不触及架构、安全、数据一致性主链；框架问题见 `docs/改造清单-一级框架.md`。
> 推进约定：本清单按业务价值排期，可与一级清单并行；接口 / 页面 / 表结构按现有模块与鉴权域落位。

## 1. 应用功能待办

| 编号 | 功能 | 模块 | 现状与依据 | 目标 | 状态 |
|------|------|------|------------|------|:---:|
| B1 | 第三方身份登录（外部身份绑定闭环） | auth + resource + admin-web + portal | V6.7 已建 `iam_external_identity`（**仅建表**）；暂无绑定/解绑逻辑与第三方登录接入 | 绑定 / 解绑逻辑 + 第三方 IdP 客户端注册（微信 / 企业微信 / 钉钉 / 支付宝 / Google / GitHub，落 `oauth2_registered_client`） + OAuth2/OIDC 登录接入（user_label=wechat 等沿用）+ admin-web 绑定管理页 / portal 我的绑定 | ⬜ |
| B2 | 应用渠道密钥签发联动（方案 A 收尾） | resource + auth | `iam_application_channel.secret_status` 已具备、密文存认证中心；渠道绑定 `sso_client_id` 已有，但**一次性签发 / 重置 / 展示流程未接通**（原 D8 方案 A 尾项） | 渠道密钥签发/重置联动认证中心客户端，UI 仅创建/重置一次性展示，详情不落库 | ⬜ |
| B3 | 组织机构管理 | resource + admin-web | `iam_org` 表 / 实体已建，`iam_app_authorization` 已支持 ORG 主体（subject_id=org_code），但**无管理 API 与页面** | 组织树管理接口 + admin-web 「组织管理」页 + 授权挑选 ORG 主体入口 | ⬜ |
| B4 | 密码策略与生命周期 | auth + admin-web | 重置密码已支持随机密码 + 强制下线；`account_*` 字段齐备但无策略 | 强密码规则 / 过期周期 / 历史复用 / 找回（邮件短信）门槛 | ⬜ |
| B5 | 能力开放与开发者门户 | resource | `iam_api_capability / iam_capability_subscription` 已建，管理端能力页可用；QPS 仅登记断言，开发者门户自服务、验签 / 沙箱未建 | `iam_capability_usage` 调用计数与限流另表 + 开发者自服务订阅 / 验签 / 沙箱环境 | ⬜ |
| B6 | 管理台易用性 | admin-web | 用户列表已支持 **user_code 缩略 + 复制（2026-08-16 ✅）**；整体仍缺查询/分页/批量 | 用户 / 客户端 / 策略 / 授权列表补齐搜索、分页、批量启用禁用 | ⬜ |
| B7 | 门户端增强 | portal + portal-web | 应用列表 mine 已按授权过滤展示；双向 SSO、卡片形态单一 | 静默授权 / 会话超时提示、门户能力卡片扩展、应用收藏排序 | ⬜ |
| B8 | 工程化与演示 | 各模块 | 服务可单个启停，无一键脚本；`test.http` 未覆盖 V6.x 新接口 | 一键启动脚本（MySQL/Redis→auth→resource→portal→admin→demos）、`test.http` 回归覆盖、三端 demo 回归 | ⬜ |
