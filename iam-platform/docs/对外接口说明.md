## 1. 认证中心（iam-authorization-server）【对应 22.1】

基址：`http://localhost:9000`

通用约定：
- **统一响应封装 `Result`**：`{"code":200,"msg":"success","data":...}`；管理端接口与认证中心自定义接口适用，`code=500` 表示业务失败。
- OAuth2 标准端点遵循 RFC 6749 / 8414 / 7009 / 8628，不使用 Result 封装。
- 管理令牌通过「密码模式」换取：`POST /oauth2/token`（admin / 123456，见 1.1.3）。

### 1.1 协议层接口【对应 22.1（一）】

#### 1.1.1 OIDC 发现 / 元数据

| 端点 | 方法 | 认证 |
|------|------|------|
| `/.well-known/openid-configuration` | GET | 公开 |
| `/.well-known/oauth-authorization-server` | GET | 公开 |

请求参数：无

```bash
curl http://localhost:9000/.well-known/openid-configuration
```

响应要点：`issuer`、`authorization_endpoint`、`token_endpoint`、`introspection_endpoint`、`revocation_endpoint`、`jwks_uri`、`userinfo_endpoint`、`device_authorization_endpoint`、`end_session_endpoint` 等。

#### 1.1.2 授权码授权端点

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/authorize` | GET | 未登录自动跳转统一登录页 |

| 参数 | 必填 | 说明 |
|------|------|------|
| `response_type` | 是 | `code` |
| `client_id` | 是 | 已注册客户端 |
| `redirect_uri` | 是 | 须与注册回跳地址一致 |
| `scope` | 否 | 空格分隔，如 `openid profile read` |
| `state` | 建议 | 回跳原样返回，防 CSRF |
| `code_challenge` / `code_challenge_method` | PKCE 客户端必填 | `S256` |

```http
GET /oauth2/authorize?response_type=code&client_id=web-app&redirect_uri=http://localhost:8086/callback&scope=openid%20read&state=demo
```

响应：`302 Location: http://localhost:8086/callback?code=xxxx&state=demo`

#### 1.1.3 令牌端点（五种 grant_type）

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/token` | POST | 客户端认证（Basic 或 body 参数）；公共客户端仅传 `client_id` |

请求头：`Content-Type: application/x-www-form-urlencoded`

| grant_type | 请求参数 |
|-----------|---------|
| `authorization_code` | `code`、`redirect_uri`；PKCE 客户端追加 `code_verifier` |
| `refresh_token` | `refresh_token` |
| `password` | `username`、`password`、`scope`（可选） |
| `device_code` | `device_code` |
| `client_credentials` | `scope`（可选） |

```bash
# 密码模式换管理令牌（admin / 123456）
curl -u web-app:123456 -d "grant_type=password&username=admin&password=123456&scope=read write" \
     http://localhost:9000/oauth2/token

# 授权码模式（含 PKCE）
curl -u portal-app:123456 -d "grant_type=authorization_code&code=xxxx&redirect_uri=http://localhost:8080/login/oauth2/code/portal-app&code_verifier=xxxx" \
     http://localhost:9000/oauth2/token
```

响应：

```json
{
  "access_token": "opaque-token-uuid",
  "token_type": "Bearer",
  "expires_in": 7200,
  "scope": "openid profile read write",
  "refresh_token": "refresh-token-uuid",
  "id_token": "eyJ...（scope 含 openid 且非客户端模式签发）"
}
```

> access_token 为 Opaque（REFERENCE）格式，撤销即删 Redis key；id_token 为 JWT（RS256）。

#### 1.1.4 Token 内省

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/introspect` | POST | 客户端认证 |

| 参数 | 必填 | 说明 |
|------|------|------|
| `token` | 是 | access_token 或 refresh_token |
| `token_type_hint` | 否 | `access_token` / `refresh_token` |

```bash
curl -u web-app:123456 -d "token=opaque-token-uuid" http://localhost:9000/oauth2/introspect
```

```json
{ "active": true, "sub": "admin", "scope": "read write", "client_id": "web-app", "aud": ["contacts-api"], "iss": "..." }
```

#### 1.1.5 Token 撤销

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/revoke` | POST | 客户端认证 |

| 参数 | 必填 | 说明 |
|------|------|------|
| `token` | 是 | 待撤销令牌 |
| `token_type_hint` | 否 | `access_token` / `refresh_token` |

```bash
curl -u web-app:123456 -d "token=refresh-token-uuid&token_type_hint=refresh_token" http://localhost:9000/oauth2/revoke
```

响应：`200`（不管存在与否一律成功）。

#### 1.1.6 JWKS 公钥

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/jwks` | GET | 公开 |

请求参数：无。响应：`{"keys":[{"kty":"RSA","use":"sig","kid":"...","alg":"RS256","n":"...","e":"AQAB"}]}`

#### 1.1.7 设备码授权

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/device_authorization` | POST | 客户端认证 |

| 参数 | 必填 | 说明 |
|------|------|------|
| `scope` | 否 | 空格分隔 |

```bash
curl -u device-app: -d "scope=openid profile" http://localhost:9000/oauth2/device_authorization
```

响应：`{"device_code":"...","user_code":"ABCD-EFGH","verification_uri":"http://localhost:9000/activate","verification_uri_complete":"...","expires_in":3600,"interval":5}`

用户验证：
- 打开验证页 `/activate?user_code=ABCD-EFGH`（公开页面）
- 提交 `POST /oauth2/device/verify`（表单：`user_code` + CSRF）
- 设备端轮询 `POST /oauth2/token`（`grant_type=urn:ietf:params:oauth:grant-type:device_code`）

#### 1.1.8 OIDC UserInfo

| 端点 | 方法 | 认证 |
|------|------|------|
| `/userinfo` | GET / POST | `Authorization: Bearer <access_token>` |

```bash
curl -H "Authorization: Bearer opaque-token-uuid" http://localhost:9000/userinfo
```

响应：`{"sub":"admin","preferred_username":"admin","updated_at":...,"email":"admin@example.com","email_verified":true}`（字段依 scope 裁剪）。

#### 1.1.9 统一登录 / 同意 / 登出（页面）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/login.html` | GET | 统一登录页 |
| `/login` | POST | 表单提交（`username`、`password`），成功后回授权流程 |
| `/consent` | GET | 授权同意页（首次授权时自动跳转） |
| `/logout` | GET | OIDC End Session：参数 `post_logout_redirect_uri`（可选）+ `id_token_hint`，或自定义 `redirect` |

```bash
curl "http://localhost:9000/logout?post_logout_redirect_uri=http://localhost:8086/logged-out"
```

#### 1.1.10 OIDC 动态客户端注册

| 端点 | 方法 | 认证 |
|------|------|------|
| `/oauth2/connect/register` | POST | 公开（Initiate Access Token 机制） |

请求体（JSON）：

```json
{
  "client_name": "示例应用",
  "redirect_uris": ["http://localhost:8090/callback"],
  "grant_types": ["authorization_code"],
  "token_endpoint_auth_method": "client_secret_basic",
  "scope": "openid profile read"
}
```

响应：返回注册后的 `client_id` / `client_secret`。

### 1.2 管理端接口【对应 22.1（二）】

通用约定：
- 基址 `http://localhost:9000`，前缀 `/api/admin/*`。
- 认证：`Authorization: Bearer <管理令牌>`（ROLE_ADMIN，令牌获取见 1.1.3 密码模式）。
- 响应统一 `Result`，`data` 见各端点说明。

#### 1.2.1 用户域 `/api/admin/users`

| 端点 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/admin/users` | GET | — | 用户列表 |
| `/api/admin/users/{id}` | GET | 路径 `id` | 用户详情 |
| `/api/admin/users` | POST | JSON body | 创建用户 |
| `/api/admin/users/{id}` | PUT | 路径 `id` + JSON body | 修改用户 |
| `/api/admin/users/{id}` | DELETE | 路径 `id` | 删除用户 |
| `/api/admin/users/{id}/enable` | PUT | 查询参数 `enabled=true|false` | 启用 / 禁用 |
| `/api/admin/users/{id}/reset-password` | POST | — | 重置密码 |
| `/api/admin/users/{id}/sessions` | GET | — | 用户 SSO 会话列表 |
| `/api/admin/users/{id}/sessions` | DELETE | — | 清理该用户全部会话 |

创建 / 修改 body（`SysUser`，仅填写需变更字段）：
> `identityType`：身份类型（非业务角色）——`1`=管理端(后台)、`2`=客户端(C端)，缺省 `2`。认证时映射为 `ROLE_ADMIN`/`ROLE_USER` authority；业务 RBAC 角色由资源中心维护。

```json
{ "username": "zhangsan", "password": "123456", "nickname": "张三", "email": "zs@example.com", "phone": "13800000000", "identityType": 2, "enabled": true }
```

调用示例：

```bash
curl -H "Authorization: Bearer 管理令牌" http://localhost:9000/api/admin/users
curl -H "Authorization: Bearer 管理令牌" -X PUT "http://localhost:9000/api/admin/users/1/enable?enabled=false"
```

#### 1.2.2 客户端域 `/api/admin/clients`

| 端点 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/admin/clients` | GET | — | 客户端列表 |
| `/api/admin/clients/{id}` | GET | 路径 `id` | 客户端详情 |
| `/api/admin/clients` | POST | JSON body | 创建客户端，返回新 `client_id` |
| `/api/admin/clients/{id}` | PUT | 路径 `id` + JSON body | 修改客户端 |
| `/api/admin/clients/{id}` | DELETE | 路径 `id` | 删除客户端 |
| `/api/admin/clients/{id}/reset-secret` | POST | — | 重置密钥，返回新 `client_secret` |

创建 body（`ClientVO`）：

```json
{
  "clientId": "my-app",
  "clientName": "我的应用",
  "clientSecret": "123456",
  "clientAuthenticationMethods": ["client_secret_basic"],
  "authorizationGrantTypes": ["authorization_code", "refresh_token"],
  "redirectUris": ["http://localhost:8090/callback"],
  "postLogoutRedirectUris": ["http://localhost:8090/logged-out"],
  "scopes": ["openid", "profile", "read", "write"],
  "requireProofKey": false,
  "requireAuthorizationConsent": false
}
```

#### 1.2.3 会话域 `/api/admin/sessions`

| 端点 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/admin/sessions/online` | GET | — | 统一在线用户列表（SSO + 客户端会话合并） |
| `/api/admin/sessions/users/{id}` | GET | 路径 `id` | 用户会话层级视图 |
| `/api/admin/sessions/users/{id}/logout` | POST | 路径 `id` | 按用户踢下线（所有设备退出） |
| `/api/admin/sessions/{ssoSessionId}/logout` | POST | 路径 `ssoSessionId` | 按 SSO 会话踢下线（仅该设备退出） |
| `/api/admin/sessions/online/{username}` | DELETE | 路径 `username` | 按用户撤销客户端令牌 |

```bash
curl -H "Authorization: Bearer 管理令牌" http://localhost:9000/api/admin/sessions/online
curl -H "Authorization: Bearer 管理令牌" -X POST http://localhost:9000/api/admin/sessions/users/1/logout
```

#### 1.2.4 授权记录域 `/api/admin/records`

| 端点 | 方法 | 参数 | 说明 |
|------|------|------|------|
| `/api/admin/records/consents` | GET | — | 授权同意主表 |
| `/api/admin/records` | GET | 查询参数 `clientId`、`principalName`（均可选） | 授权历史 |
| `/api/admin/records` | DELETE | 查询参数 `clientId` + `principalName`（必填） | 取消授权（同时强制下线） |

```bash
curl -H "Authorization: Bearer 管理令牌" http://localhost:9000/api/admin/records
curl -H "Authorization: Bearer 管理令牌" -X DELETE "http://localhost:9000/api/admin/records?clientId=web-app&principalName=user"
```

## 2. 资源中心（iam-resource-service）【对应 22.2】

定位：业务 RBAC 资源中心（角色 / 权限 / 关联）。对外提供**三类接口能力**（管理端 / portal 端 / 公开端），另有服务间内部能力供认证中心 M2M。

- **管理端**：角色、权限编辑保存（`ROLE_ADMIN`，与管理台平级；管理后台专用）。
- **portal 端**：客户端目录（门户 SSO 跳转卡片所需，特权客户端）。
- **公开端**：通讯录等三方业务 API（任意已认证用户）。
- **内部（不属对外分类）**：`/api/internal/**`，供认证中心 M2M 取角色/权限（`ROLE_SERVICE`）。

控制器包对应：`controller/admin`（管理端）、`controller/portal`（portal 端）、`controller/client`（公开端）、`controller/internal`（服务间内部）。

### 2.1 管理端能力（Bearer + `ROLE_ADMIN`，`controller/admin`）

**角色域**

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/roles` | 角色列表（含 permissionIds） |
| POST | `/api/admin/roles` | 新增角色（code 唯一） |
| PUT | `/api/admin/roles/{id}` | 修改角色名称 / 备注，可重绑权限 |
| DELETE | `/api/admin/roles/{id}` | 删除角色（级联清关联） |

请求体（新增 / 修改，修改时 permissionIds 控制重绑）：

```json
{ "code": "MANAGER", "name": "部门经理", "remark": "", "permissionIds": [1, 2, 3] }
```

**权限域**

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/permissions` | 权限列表（type 默认 `app`，如 `app:portal`） |
| POST | `/api/admin/permissions` | 新增权限（code 唯一） |
| PUT | `/api/admin/permissions/{id}` | 修改权限名称 / 备注 / type |
| DELETE | `/api/admin/permissions/{id}` | 删除权限（级联清关联） |

```bash
curl -H "Authorization: Bearer $TOKEN" http://localhost:9010/api/admin/roles
```

> 现状：用户 ↔ 角色分配（`assignRolesToUser` / `listRoleIdsOfUser`）已实现于服务层但未暴露 REST；管理台"按人查/分配角色"规划为 `/api/admin/users/{id}/roles`（`ROLE_ADMIN`），不并入内部接口。

### 2.2 portal 端能力（门户客户端目录，`controller/portal`）

portal 是特权客户端（与管理端平级），门户经 BFF 拉取应用目录做 SSO 跳转卡片。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/public/clients` | 门户可跳转的客户端列表（透传认证中心目录 API，60s 缓存） |

```bash
curl http://localhost:9010/api/public/clients
```

> 当前为 `permitAll`（portal 端与公开端均可用）；若收紧为 portal 专属，改为校验 `client_id == portal-app` 并调整安全规则。

### 2.3 公开端能力（任意已认证用户，`controller/client`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/contacts` | 返回 sub 对应身份 / 角色 / 权限 + 通讯录（硬编码） |
| GET | `/api/contacts/{id}` | 通讯录详情 |

```bash
curl -H "Authorization: Bearer $TOKEN" http://localhost:9010/api/contacts
```

响应示例：

```json
{ "code": 0, "data": { "requested_by": "admin", "aud": "web-app", "scope": "read",
  "user": { "id": 1, "username": "admin", "nickname": "系统管理员",
            "identityType": 1, "enabled": 1 },
  "roles": ["ADMIN"], "permissions": ["app:portal", "app:oa", "app:crm", "app:erp", "app:bi"],
  "contacts": [ { "id": 1, "name": "张三" } ] } }
```

### 2.4 服务间内部能力（不属对外分类，M2M，`controller/internal`）

仅面向服务间调用（认证中心 M2M 及未来对外 API 服务平台）；普通用户 / 管理端 / portal 令牌均不可访问。
鉴权：`ROLE_SERVICE`（由 `grant_type=client_credentials` 或 client_id ∈ `authserver.service-client-ids` 触发注入）+ **client_id 白名单**双保险。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/internal/user/{username}/roles` | 按用户名返回 `{username, roles:["ROLE_xxx"], permissions:["app:portal",...]}`，只含编码不含凭据 |

```bash
# 以 resource-server 的 client_credentials 令牌调用
curl -H "Authorization: Bearer $SERVICE_TOKEN" http://localhost:9010/api/internal/user/admin/roles
```

响应示例：

```json
{ "code": 0, "data": { "username": "admin",
  "roles": ["ROLE_ADMIN"],
  "permissions": ["app:portal", "app:oa", "app:crm", "app:erp", "app:bi"] } }
```

> 现状（2026-08）：本接口已就绪但**尚无调用方**，认证中心 id_token claims 暂由本库 `PortalUserDetailsService` 直接提供（改造清单 #17 ⬜）。
