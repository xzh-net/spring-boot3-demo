# 统一认证管理系统 — 需求设计说明文档

> **文档版本**：v2.0  
> **生成日期**：2026-08-11  
> **变更说明**：采用双向 SSO 方案，补充设备码授权模式

---

## 一、系统概述

基于 Spring Boot + Spring Security OAuth2 构建统一认证管理系统，支持三种角色体系、多端独立会话、以及门户与客户端之间的**双向 SSO 自动登录**。认证协议同时支持**授权码模式**（适用于浏览器端）和**设备码模式**（适用于 TV、IoT 等无浏览器设备）。

---

## 二、角色定义

| 角色 | 访问入口 | 登录方式 | 说明 |
|------|----------|----------|------|
| **系统管理员** | `http://host:9000/admin` | 独立登录页面（账号密码） | 后台管理操作，拥有最高权限 |
| **普通用户** | `http://host:9000/` | 门户登录页面（账号密码） | 进入门户后可跳转各客户端 |
| **客户端用户** | 各客户端地址（8080/8081/8082） | OAuth2 协议登录（支持授权码 + 设备码两种模式） | 第三方业务系统接入用户 |

## 四、功能需求详述

### 4.1 管理端（`/admin`）需求

| 编号 | 需求点 | 详细说明 |
|------|--------|----------|
| A-01 | 独立登录界面 | 管理员通过独立的 `/admin/login` 页面登录，与门户登录界面物理隔离 |
| A-02 | 多端多会话 | 同一管理员账号可在多个浏览器/设备同时登录，各自保持独立会话 |
| A-03 | 会话隔离 | 退出或下线操作仅影响当前管理员自己的会话实例，不影响其他管理员的会话 |
| A-04 | 会话类型独立 | 管理员会话与普通用户会话、客户端会话**完全独立**，互不干扰 |
| A-05 | 下线自己 | 管理员主动下线/退出时，仅销毁自身当前管理端会话 |
| A-06 | 不受 SSO 影响 | 管理端会话不参与任何 SSO 流程，保持完全独立 |

### 4.2 用户门户（`/`）需求

| 编号 | 需求点 | 详细说明 |
|------|--------|----------|
| P-01 | 独立登录界面 | 普通用户通过门户登录页登录，与管理端登录界面物理隔离 |
| P-02 | 多端多会话 | 同一用户可在多个浏览器/设备同时登录门户，各自保持独立会话 |
| P-03 | 会话隔离（内部） | 退出/下线操作仅影响当前用户自己的门户会话，不影响其他用户的门户会话 |
| P-04 | 会话隔离（外部） | 退出/下线操作**不影响**其他客户端的已登录状态（客户端会话独立销毁） |
| P-05 | 会话隔离（纵向） | 用户门户会话与管理员会话为两条独立数据，生命周期完全独立 |
| P-06 | SSO 自动跳转→客户端 | 用户在门户登录后，跳转到任一客户端时，客户端通过 OAuth2 授权码流程自动识别门户登录态，实现**免二次登录** |
| P-07 | SSO 自动跳转←客户端 | 用户在客户端登录后，跳转到门户时，门户通过 OAuth2 授权码流程自动识别客户端登录态，实现**免二次登录** |

### 4.3 客户端（8080/8081/8082）需求

| 编号 | 需求点 | 详细说明 |
|------|--------|----------|
| C-01 | OAuth2 协议登录 | 客户端通过 OAuth2 授权码流程跳转到认证中心完成认证 |
| C-02 | 支持设备码模式 | 对于无浏览器设备（TV、IoT 等），客户端提供设备码登录入口，用户在手机/PC 上完成认证 |
| C-03 | 多端多会话 | 同一用户在同一客户端可多浏览器/设备同时登录，各自独立 |
| C-04 | 多端隔离（内部） | 退出/下线操作仅影响当前用户自己的该客户端会话，不影响其他用户 |
| C-05 | 多端隔离（横向） | 退出/下线操作**不影响**其他客户端（如退出 8080 不影响 8081、8082） |
| C-06 | 多端隔离（纵向） | 退出/下线操作**不影响**门户的已登录状态 |
| C-07 | SSO 自动跳转→门户 | 用户在客户端登录后，点击跳转门户时，门户自动识别客户端登录态，实现**免二次登录** |
| C-08 | SSO 自动跳转←门户 | 用户在门户登录后，点击跳转客户端时，客户端自动识别门户登录态，实现**免二次登录** |
| C-09 | 多客户端独立 | 用户同时在线于 8080、8081、8082 时，各自的退出/下线互不影响 |

### 5.3 会话约束规则

| 约束编号 | 约束描述 | 说明 |
|----------|----------|------|
| S-01 | **会话按域隔离** | 管理员、门户、每个客户端各有独立 Session 存储域 |
| S-02 | **会话实例唯一** | 每个登录实例有唯一 Session ID，下线按 Session ID 精确销毁 |
| S-03 | **用户-会话一对多** | 同一用户在同域可同时拥有多个有效会话（多浏览器/多设备） |
| S-04 | **下线粒度 = 单会话** | 下线仅销毁当前实例 Session，不销毁同域内该用户的其他会话 |
| S-05 | **跨域退出不联动** | 任何域的退出不影响其他域的会话状态 |
| S-06 | **SSO 双向往来** | 门户与客户端之间可互认登录态，自动免登录；但 SSO 仅在**同一次跳转链路**中生效 |
| S-07 | **SSO 会话双轨** | 通过 SSO 建立的会话，在目标域创建独立 Session，与源域 Session 独立生命周期 |
| S-08 | **管理端独立** | 管理端不参与任何 SSO 流程 |

## 六、SSO 双向登录流程

### 6.1 模式一：授权码模式（Authorization Code）

适用于**浏览器端**，标准 OAuth2 授权码流程。

#### 6.1.1 门户 → 客户端 SSO

```
  [用户浏览器]                    [认证中心 :9000]              [客户端 :8080]
       │                               │                          │
       │ ①. 已登录门户 (持有 PORTAL_SESSION)                       │
       │                               │                          │
       │ ②. 点击客户端入口链接          │                          │
       │ ───────────────────────────────────────────────────► │
       │                               │                          │
       │ ③. 客户端检查未登录，发起 OAuth2 授权码请求                  │
       │ ◄────────────────────────────────────────────────── │
       │                               │                          │
       │ ④. 浏览器跳转至认证中心 /oauth2/authorize                   │
       │ ─────────────────────────► │                             │
       │                               │                          │
       │ ⑤. 认证中心检测到有效 PORTAL_SESSION（SSO 匹配）             │
       │    自动跳过登录确认页           │                          │
       │                               │                          │
       │ ⑥. 直接签发 Authorization Code（code）                     │
       │ ◄───────────────────────── │                             │
       │                               │                          │
       │ ⑦. 浏览器携带 code 跳回客户端 redirect_uri                 │
       │ ───────────────────────────────────────────────────► │
       │                               │                          │
       │ ⑧. 客户端用 code 换 Token，创建 CLIENT_8080_SESSION         │
       │                               │                          │
       │ ⑨. SSO 完成，用户同时持有 PORTAL_SESSION + CLIENT_8080_SESSION
       │    两个 Session 独立生命周期，互不影响                       │
```

| 步骤 | 关键动作 | 说明 |
|------|----------|------|
| ⑤ | SSO 会话匹配 | 认证中心从 Cookie 中检测 PORTAL_SESSION，校验用户身份 |
| ⑥ | 自动授权 | 无需用户再次输入账号密码，直接签发授权码 |
| ⑧ | 独立创建会话 | 客户端收到 code 后创建自己域的 Session，与门户 Session 无关 |
| ⑨ | 双轨并行 | 后续退出客户端只销毁 CLIENT_8080_SESSION，保留 PORTAL_SESSION |

#### 6.1.2 客户端 → 门户 SSO

```
  [用户浏览器]                    [认证中心 :9000]              [客户端 :8080]
       │                               │                          │
       │ ①. 已登录客户端 (持有 CLIENT_8080_SESSION)                  │
       │                               │                          │
       │ ②. 点击"返回门户"链接          │                          │
       │ ◄────────────────────────────────────────────────── │
       │                               │                          │
       │ ③. 门户检测未登录，发起 OAuth2 授权码请求                    │
       │ 跳转到认证中心 /oauth2/authorize                          │
       │ ─────────────────────────► │                             │
       │                               │                          │
       │ ④. 认证中心检测到有效 CLIENT_8080_SESSION（SSO 匹配）       │
       │    自动跳过登录确认页           │                          │
       │                               │                          │
       │ ⑤. 直接签发 Authorization Code（code）                     │
       │ ◄───────────────────────── │                             │
       │                               │                          │
       │ ⑥. 浏览器携带 code 跳回门户 redirect_uri                   │
       │ ─────────────────────────► │                             │
       │                               │                          │
       │ ⑦. 门户用 code 换 Token，创建 PORTAL_SESSION               │
       │                               │                          │
       │ ⑧. SSO 完成，用户同时持有 CLIENT_8080_SESSION + PORTAL_SESSION
       │    两个 Session 独立生命周期，互不影响                       │
```

### 6.2 模式二：设备码模式（Device Authorization）

适用于**无浏览器设备**（如智能 TV、IoT 设备、打印机等），用户在有浏览器的设备上完成认证。

#### 6.2.1 设备码 SSO 登录流程

```
  [设备终端]                     [用户手机/PC浏览器]             [认证中心 :9000]
       │                               │                          │
       │ ①. 用户在设备端启动登录         │                          │
       │ ─────────────────────────► │                             │
       │    (或用户在设备上直接发起 OAuth2 device_authorization 请求) │
       │                               │                          │
       │ ②. 认证中心返回 user_code + verification_uri                │
       │ ◄───────────────────────── │                             │
       │    例: user_code=ABCD-EFGH                                   │
       │    verification_uri=http://host:9000/activate              │
       │                               │                          │
       │ ③. 设备显示验证码和二维码       │                          │
       │    ┌─────────────────────┐   │                          │
       │    │  请在手机上访问:     │   │                          │
       │    │  http://host:9000/  │   │                          │
       │    │  activate           │   │                          │
       │    │                     │   │                          │
       │    │  输入验证码:         │   │                          │
       │    │  ABCD-EFGH          │   │                          │
       │    │                     │   │                          │
       │    │  [二维码]            │   │                          │
       │    └─────────────────────┘   │                          │
       │                               │                          │
       │ ④. 用户用手机/PC 访问 verification_uri                    │
       │                               │                          │
       │ ⑤. 手机浏览器检测 SSO 状态     │                          │
       │    ├─ 已登录门户 → 自动确认授权                               │
       │    ├─ 已登录某客户端 → 自动确认授权                           │
       │    └─ 未登录 → 显示登录页 → 登录后自动确认授权                  │
       │                               │                          │
       │ ⑥. 认证中心收到确认，标记 device_code 为已授权                  │
       │                               │                          │
       │ ⑦. 设备终端轮询 token 端点，检测到授权已完成                    │
       │ ─────────────────────────► │                             │
       │                               │                          │
       │ ⑧. 设备获取 Token，完成登录     │                          │
       │                               │                          │
       │ ⑨. 设备独立创建 CLIENT_SESSION，与手机/PC 的 Session 独立       │
```

| 步骤 | 关键动作 | 说明 |
|------|----------|------|
| ① | 请求设备码 | 设备向认证中心 `oauth2/device/code` 发起请求 |
| ② | 返回验证码 | 认证中心返回 `user_code` 和用户需访问的 `verification_uri` |
| ③ | 展示验证码 | 设备以文字 + 二维码方式引导用户在其他设备上认证 |
| ④ | 手机扫码 | 用户在手机/PC 浏览器访问 `verification_uri`，输入或自动填入 `user_code` |
| ⑤ | SSO 联动 | 手机/PC 上的 SSO 会话自动完成授权确认（已登录则直接确认，未登录则登录后确认） |
| ⑦ | 轮询授权结果 | 设备定时轮询 `oauth2/token` 端点查询授权状态 |
| ⑨ | 会话独立 | 设备获得的 Session 与手机/PC 的 Session 完全独立 |

## 八、OAuth2 端点需求

### 8.1 认证中心需暴露的端点

| 端点 | 模式 | 说明 |
|------|------|------|
| `GET /oauth2/authorize` | 授权码 | 浏览器端授权码模式入口，支持 SSO 自动确认 |
| `POST /oauth2/token` | 授权码 + 设备码 | 用 code 或 device_code 换 Token |
| `POST /oauth2/device/code` | 设备码 | 设备码模式发起授权请求 |
| `GET /activate` | 设备码 | 用户在手机/PC 上确认设备码授权的页面 |
| `POST /activate/confirm` | 设备码 | 确认授权并绑定用户身份 |

### 8.2 授权码模式参数约束

| 参数 | 说明 |
|------|------|
| `response_type=code` | 固定值，使用授权码模式 |
| `client_id` | 客户端标识，每个客户端独立注册 |
| `redirect_uri` | 回调地址，需与注册时一致 |
| `scope` | 请求的权限范围 |
| `state` | CSRF 防护随机值，原样返回 |

### 8.3 设备码模式参数约束

| 参数 | 说明 |
|------|------|
| `client_id` | 客户端标识 |
| `scope` | 请求的权限范围 |
| 返回 `device_code` | 设备用于轮询的授权码 |
| 返回 `user_code` | 用户需输入的验证码（如 ABCD-EFGH） |
| 返回 `verification_uri` | 用户需访问的确认页面 URL |
| 返回 `verification_uri_complete` | （可选）含 user_code 的完整 URL，用于扫码直达 |
